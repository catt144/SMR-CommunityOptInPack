- **THREE separate implementations of `GatherAvailableColonists` — ⛔ do not assume one hook
  reaches them all:**

| implementation | pool | used by |
|---|---|---|
| `CargoTransporter:…` (`Buildings/CargoTransporter.lua:237`) | `city.labels.Colonist` + `GetConnectedCitiesForColonists` — **colony-wide auto-draft** | legacy expeditions, via `RocketExpeditionBase:…` (`RocketExpedition.lua:496-497`) which calls it explicitly |
| `LanderRocketBase:…` (`Buildings/LanderRocket.lua:1149`) | `self.cargo_passengers` — **player-filled**, written by `LanderRocketCargoRequest:SetPassengers`/`ApplyPassengers` (`:253-283`) | asteroid landers |
| `CargoTransporterNew:…` (`CargoTransporterNew.lua:235`) | its own colony/connected-city pool | **1.1.0 Universal rocket expeditions**, trade / supply / colony transfer |

The receiver distinction is measured by C95's attended re-point (`733bed2`, linked
from C95), and the unshipped return exploration (`194f4c3`) again acted on
UniversalZeusRocket(1053). References below to the old RocketExpedition bodies
describe the legacy path; they are not proof that the New receiver executes them.

- **Selection order in the colony-wide draft** (`CargoTransporter.lua:237-292`):
  1. Pool = `city.labels.Colonist` + connected cities. ⛔ **No distance, dome, quarantine,
     shuttle or rail check exists anywhere in this function.** Proximity is not a qualification.
  2. ⚠️ **Silent pre-filter:** `if not quick_load`, anyone with `unit.thread_running_destructors`
     is dropped with no log line. Expeditions call `Load(self, manifest)` with no `quick_load`
     (`RocketExpedition.lua:536`), so this filter **is live** for them.
  3. Bucketed by `local idle = command == "Idle" or command == "Abandoned"` and
     `local employed = IsKindOf(unit.workplace, "Workplace")`, walked in order
     **idle+unemployed → busy+unemployed → idle+employed → busy+employed**. ⇒ employment is the
     primary key and activity only the tiebreaker: a jobless sleeper is taken before an employed
     idler. ⭐ `Rest` is its own command (`Colonist.lua:2371`, `:2572`), so **resting is BUSY**.
  4. Each bucket passes through `FilterColonistsByTrait(pool, label, amount - #list)`.
- ⭐ **THE FOUR-BUCKET SORT EXISTS TWICE, and the copies are not identical** (added 2026-09-16 on the
  owner's question). `CargoTransporterNew:GatherAvailableColonists` (`CargoTransporterNew.lua:235-287`,
  used by Universal rockets and the space elevator) repeats the same buckets and the same walk order.
  **It adds a liveness guard the legacy copy does NOT have:**
  `if idle and not unit:IsDead() or not idle and unit:CanChangeCommand()`.
  ⇒ the legacy draft can bucket a colonist the New receiver would skip; the New guard also applies
  to 1.1.0 Universal rocket expeditions.
- ⛔ **A SHORT CREW IS A PERMANENT WAIT, NOT A SMALLER CREW.** `GatherAvailableCargo` returns `false`
  when `#new_crew < count` (`CargoTransporter.lua:196-199`) and `Load` then loops
  `while not succeed do Sleep(1000)` (`:124-130`); expeditions call `Load(self, manifest)` with no
  `quick_load` and no `transfer_available` (`RocketExpedition.lua:536`), so the retry loop is live and
  the gather re-picks the same top-bucket colonists every second. ⇒ **anything that removes a
  colonist AFTER the gather returns hangs the rocket**; a filter has to reach the pool.
- ⛔ **The two filters behave completely differently, and this is the trap.**
  `FilterColonistsByTrait` (`CargoTransporterNew.lua:197-227`):
  - **Hard, never relaxed:** if `trait ~= "Colonist"`, the pool is cut to `col.traits[trait]`
    first. A colonist without the demanded specialisation is eliminated before any bucketing and
    no later step can recover them. ⇒ a specialised anomaly will pull a working specialist off a
    job rather than take an idle generalist, because the generalist is not a candidate at all.
  - **Soft, progressively relaxed:** `build_unfavored_traits` (`:191-195`) is only
    `{ "Tourist" }` plus `{ "Child" }` plus `{ "Senior" }` unless `g_SeniorsCanWork`. If the crew
    cannot be filled these are dropped one at a time and the excluded are re-admitted.
  - ⭐ Specialisation reaches here from `anomaly.requirements.crew_specialization`
    (`RocketExpedition.lua:128`, `:526-528`); `nil` or `"any_specialization"` normalises to
    `"Colonist"` (`CargoTransporter.lua:238`) and the hard filter is skipped entirely.
- ⭐ **Boarding is instantaneous and that is not a bug.** `ExpeditionLoadCrew` sets
  `SetCommand("EnterTransporter", self)` (`CargoTransporter.lua:295-299`); the command body
  (`Colonist.lua:5025-5044`) saves the home, clears the dome, then calls
  `Unit:EnterTransporter` (`Unit.lua:1292-1306`) which sets the holder and `Disappear`s them.
  **There is no goto, no walk, no shuttle and no train.** Watching a rocket for boarding
  colonists is watching for something that never happens.
- ⚠️ **"Failure is visible" is ITSELF UNVERIFIED — reopened 2026-09-16.** An unfillable manifest is
  *meant* to set `colonist_summon_fail` (`RocketExpedition.lua:498`) so the rocket's panel reads
  **"Not enough Colonists"** (`T(11473)`, `:1151`), and `CargoTransporter:Load` retries forever
  (`:124-130`), so the wait is indefinite but labelled. ⛔ **There is no notification either way** —
  the status lives only on the rocket's own panel, beside "No free rover" and "Not enough Drones".
- ⛔⛔ **AND THE LINE THAT SETS THAT FLAG DEREFERENCES A NIL.** The picker returns **nil**, not a
  short list, when it cannot fill (`CargoTransporter.lua:284-291`); the expedition override then does
  `self.colonist_summon_fail = #crew < amount` (`RocketExpedition.lua:498`) with **no guard**, while
  `GatherAvailableCargo` one level further out *does* guard the same value with `or empty_table`
  (`:196`). ⚠️ **Byte-identical in 1.0.7** (`RocketExpedition.lua:494`) — not a 1.1.0 regression.
  ⇒ On the expedition path (`Load(self, manifest)`: no `quick_load`, no `transfer_available`) the nil
  branch is **reached every time a crew is short.** ⛔ **What `#nil` does in this engine is UNKNOWN.**
  If it errors, the Load thread dies, the flag is never set, the panel stays blank and the rocket
  waits forever — **indistinguishable from the intended patient wait.**
