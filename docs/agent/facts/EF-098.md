- **SOURCE, the meteor target.** `Data/CheatDef.lua:244-284` — `Meteor`, `MeteorMultiSpawn`, `MeteorStorm` each
  run `CheatPickFromList(...)` then `NetSyncEvent("Cheat", "CheatMeteors", "<type>", chosen, GetCameraLookAtPassable())`.
  The position is where the camera is centred, so the strike lands at screen centre regardless of the cursor.
- **SOURCE, the silent no-op.** `Lua/Cheats.lua:40-49`: `function CheatMeteors(meteors_type, setting, pos) if pos then
  ... CreateGameTimeThread(function() MeteorsDisaster(descr, meteors_type, pos) end) end end`. No `else`, no
  print, no error: a nil or unresolvable look-at produces nothing and reports nothing. The devs' own tests pass
  an explicit position (`Lua/Dev/GameTests.lua:329-338`).
- **MEASURED, the re-entering presets.** Splitting `Data/CheatDef.lua` on `PlaceObj('CheatDef'` gives 105 blocks;
  13 contain `NetSyncEvent`: `ColdWave`, `DustDevil`, `DustDevilMajor`, `DustStorm`, `DustStormElectrostatic`,
  `DustStormGreat`, `Marsquake`, `Meteor`, `MeteorMultiSpawn`, `MeteorStorm`, `Rains`, `FinishMystery`,
  `StartMystery`. Each is `sync = false` (so the picker UI opens once) and then syncs the chosen action
  through `NetSyncEvents.Cheat`, which calls `LogCheatUsed` (`EF-095`). The other 92 `run` bodies call their
  leaf directly (e.g. `StopDisaster` → `CheatStopDisaster()`, `CheatDef.lua:300-309`; `CompleteAllConstructions`
  → `CheatCompleteAllConstructions()`, `:370-378`; `FillAllStorages` → `AllMapsForEach(true, "MechanizedDepot",
  "StorageDepot", function(o) o:CheatFill() end)`, `:387-395`).
- **SOURCE, the cursor route.** `GetTerrainCursor()` (used by `UndergroundCaveIn`'s `param_values`, `CheatDef.lua:315-326`,
  and `CommonLua/Camera.lua:786`) and `GetCursorWorldPos()` are both open to mods (`EF-096`).
- ⇒ For a tool: call `CheatMeteors("single", <setting or nil>, GetTerrainCursor())` and the like; never
  `def:run()` for the 13 above. `CheatStopDisaster()` (`Cheats.lua:51-53`, `Msg("CheatStopDisaster")`) is clean.
