- **MEASURED SHAPE:** the first `SilentHitMomentFX` run loaded all 11 moment
  presets, but its `OnMsg.LoadGame` pass logged zero starts because every
  candidate was gated on `not IsValidThread(saved_handle)`. The first post-load
  read then showed the hammer and Excavator FX handles dead
  (`archive/c74build_initial_Mars.exe-20260910-16.20.36.log:126,142,269`).
- The only runtime-relevant change was to remove that liveness skip and replace
  eligible trackers. On the same save, the next run replaced four trackers on
  each of two loads (`archive/c74build_final_Mars.exe-20260910-16.47.24.log:178,294`),
  and the owner heard every intended effect with no power cycle. Both logs have
  zero `[LUA ERROR]` and zero `[ERROR]`.
- **INFERRED scheduling explanation:** the persisted handle still reports valid
  while `OnMsg.LoadGame` runs, before its resumed no-marker thread finishes
  exiting. The before/after experiment proves the stale-liveness window, not
  the precise scheduler instruction where the handle changes state.
- **NARROW RULE:** this does not license replacing arbitrary gameplay threads.
  It is safe here because the threads are cosmetic-only, their vanilla starter
  owns the field, and replacement first deletes the prior handle. When those
  conditions hold, replace synchronously on load rather than using
  `IsValidThread` as proof that a persisted tracker will remain alive.
