- ⛔ **1.0.7 SAVES DO NOT LOAD ON 1.1.0.** (Owner screenshots, 2026-09-08.) The
  load list marks them **"Deprecated save file format!"** in red, and attempting
  one raises: *"This savegame is from an older version of Surviving Mars:
  Relaunched. To load it, right-click the game in Steam, go to Properties > Game
  Versions & Betas, and select the 1.0.7 version."* This is a **refusal, not a
  warning with a continue** — there is no convert-and-load path offered.
- ⛔ **THE WHOLE PLAYTEST SAVE LIBRARY IS BRANCH-LOCKED TO 1.0.7.** Everything
  the project provisioned — `USA Sol 302` / `Sol 298` (26+ hours playtime, the
  heavy-colony fixture), `F95 Baseline` / `F95 fresh` / `f95 healed`, `F90
  Alert`, `F59 Test1/test2`, `T1-UNINSTALL(-R)` / `T2-Uninstall(-R)`, and the
  rest — is reachable **only** by switching the install back to the 1.0.7
  branch. ⚠️ This is the single largest cost the update imposed on this project:
  those saves are the substrate of nearly every A/B the pack has ever run.
- ⚠️ **WHAT A 1.1.0 LEG NOW COSTS.** A fresh colony, provisioned from zero. The
  project's own rule (`playtest saves are provisioned first`) distinguishes the
  **hours of solo provisioning** needed for a NEW heavy setup from the
  **20-30 min organic warm-up** before a one-off test — a 1.1.0 leg is
  emphatically the first kind, and any plan that budgets the second is wrong.
  ⛔ Never again describe our testing exposure on 1.1.0 as "short and simple".
- ✅ **DECISION 98's DEV CLAIM IS NOW ROUTE-CHECKED BY THE GAME ITSELF.** The
  1.0.7 branch was previously only a line in a store announcement — a dev claim
  about a store surface. The **game's own refusal dialog names the exact route**
  (Properties → Game Versions & Betas → 1.0.7), which is a far stronger witness.
  ⚠️ Still not walked to completion: nobody has yet selected it and confirmed the
  download and a successful load.
- **The fork this creates, and it is the owner's** (decision 98): a 1.0.7 branch
  install keeps the entire fixture library and every historical A/B reproducible,
  but tests the version players are leaving; a 1.1.0 install tests what players
  actually run but starts the fixture library again from nothing. ⚠️ They are not
  exclusive — Steam switches branches per install — but each switch is a full
  re-download of a ~10 GB game.
- ⭐ **A DEDUCTION ABOUT `F114`, FLAGGED AS A DEDUCTION.** Because 1.0.7 saves
  cannot load at all, the reporter of the trains defect cannot be on a converted
  old save: they are on a colony **created on 1.1.0**. ⇒ the repro target is a
  **fresh 1.1.0 game**, and save-format conversion is excluded as a confound.
  ⚠️ The one alternative not excluded: a save they made earlier on 1.1.0 itself.
- ⚠️ **`EF-056` still binds and is now sharper**: loading a COPY of a campaign runs
  that campaign's autosave rotation and **deletes the owner's autosaves**
  (`EF-056`). With the 1.0.7 library irreplaceable and branch-locked, a careless
  copy-load on the 1.0.7 branch would destroy fixtures that can no longer be
  regenerated on the current build. Pre-copy every autosave, every time.
