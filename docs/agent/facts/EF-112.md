- **SOURCE — dispatch is polymorphic.** `Drone:Work` assigns and fulfils a real request, fills
  `w_request`/`request_amount`/`resource`/`amount`/`target`, approaches the source, then calls
  `building:DroneWork(self, request, resource, amount)` (`Lua/Units/Drone.lua:983-1022`). It has no
  fixed animation or FX name of its own.
- **SOURCE — broken track uses construction visuals.** `BreakTrackElement` places a
  `TrackGridElement` construction site (`Lua/Buildings/Track.lua:623-645`), whose `DroneWork`
  delegates to `ConstructionSite.DroneWork` (`Lua/Buildings/TrackElement.lua:726-732`). That body
  calls `ContinuousTask` with `"constructStart"`, `"constructIdle"`, `"constructEnd"` and FX
  `"Construct"` (`Lua/Buildings/ConstructionSite.lua:1465-1476`).
- **SOURCE — exact presentation lifecycle.** `ContinuousTask` calls `StartFX`, plays the start state,
  sets the idle state, drains the request, calls `StopFX`, and plays the end state
  (`Lua/Units/Drone.lua:798-829`). `Unit:StartFX`/`StopFX` emit `PlayFX(fx, "start"/"end", actor,
  target)` and clear the stored FX tuple (`Lua/Units/Unit.lua:79-101`). A command return enters
  `Idle`, whose state is `"idle"` (`CommonLua/Classes/CommandObject.lua:262-283`; `Drone.lua:653-666`).
- **SOURCE — maintenance differs.** `RequiresMaintenance:DroneWork` uses
  `"repairBuildingStart"`, `"repairBuildingIdle"`, `"repairBuildingEnd"`, FX `"Repair"`
  (`Lua/RequiresMaintenance.lua:655-680`). These are valid building-repair visuals, not the native
  broken-track-site choice.
- **SOURCE — grouped track completion.** The construction work destructor calls dynamic
  `self:Complete()` only when funded and constructed (`ConstructionSite.lua:1465-1476`). For track
  groups, `ConstructionGroupLeader:Complete()` completes each member, and
  `TrackConstructionSite:Complete()` restores the hidden broken element and reconnects the track
  (`ConstructionSite.lua:2659-2705`; `TrackElement.lua:841-915`). The generic
  `ConstructionSite:Complete` body is not the broken track's concrete completion body.
- **CONTROL.** Recheck the four exact string tuples plus the `building:DroneWork` call in the cited
  archived files. A changed tuple, delegate or target class falsifies this fact. Do not call
  `Drone:Work`/`ContinuousTask` with a fake request merely for presentation: both mutate the request
  and battery; a scripted visual must own its cleanup separately.
