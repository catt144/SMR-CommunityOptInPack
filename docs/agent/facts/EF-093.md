- **SOURCE, game 1.1.0.403908, all citations `CommonLua/Features/LockablePreset.lua`
  unless named.** `OnMsg.PostLoadGame` calls `PreProcessLockablePresets()` with no
  `init` argument (`:468-471`). Its loop walks every `LockablePreset` and, for any
  preset **absent from** `owner.ProcessedLockablePresets`, calls
  `ResetLockablePresetState(preset, owner)` (`:434-452`).
- **SOURCE, what the re-seed does** (`:402-415`): `lClearLockState(preset, owner)`,
  then `RecalcLockablePresetPrerequisites(preset, owner, "initial")`, then
  `if preset.LockState ~= "enabled" then AddPresetLockStateReason(preset, preset.LockState, …)`,
  then `owner.ProcessedLockablePresets[preset] = true`. ⇒ the preset's **declared**
  lock state is restored from data, not from the save.
- **SOURCE, both halves are PERSISTED.** `PresetLockStates` and
  `ProcessedLockablePresets` are `LockablePresetOwner` properties (`:5-7`, `no_edit`),
  and the owner is the `Player` (`CommonLua/Classes/Player.lua:10`).
- **SOURCE, the default is `"enabled"`, NOT the preset's own value.**
  `GetPresetLockStateAndText` returns `"enabled"` whenever the owner has no entry for
  that preset (`:343-358`, three separate early returns). So a declared `hidden`
  reaches the player **only** through the seeding above — remove the entry and the
  tech reads as enabled, not as hidden.
- ⭐ **THE CONSEQUENCE FOR MODS.** Clearing a lock reason *and* dropping the preset
  from `ProcessedLockablePresets` leaves the save in a shape **vanilla repairs by
  itself** on the next load. This is a residue class the pack has no name for yet:
  not an inert leftover and not an orphan thread, but an **omission vanilla already
  knows how to fix**. It needs no `SaveGameStart` tear-down (`FIX_POLICY` §3a layer 1),
  no save-rescue artifact (`D13`) and no player action.
- ⚠️ **UNVERIFIED, and load-bearing if anyone builds on this:** a mod that wants to
  keep suppressing while installed needs its own `PostLoadGame` handler to run
  **after** vanilla's re-seed. Handler order is unmeasured; `UnhideUnlockedTechs`
  (`Lua/TechTree.lua`) also sits on that message, so the seam is already crowded.
- ⚠️ `ProcessedLockablePresets` is keyed by the **preset table**, not an id string,
  so it rides the engine's permanents mechanism across a save. A preset the vendor
  later deletes leaves a dangling key; the effect of that is unread.
- ⚠️ `:477` warns that the build order "must match on all network clients". Single
  player makes that moot here, but it marks the set as order-sensitive engine state.
- ⛔ **SOURCE-derived only; never observed in play.** Nothing in the pack uses this
  seam today. Found 2026-09-13 while pricing C92's restoration residue.
