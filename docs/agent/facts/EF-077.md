- ⚠️ **WE CLEAR THE FLOOR BY EXACTLY ZERO.** (Source-read 2026-09-08 against
  the 1.1.0 tree.) 1.1.0 sets **`ModMinLuaRevision = 350453`**
  (`CommonLua/Modding/Mod.lua:15`, beside `ModRequiredLuaRevision = 350453`);
  our `metadata.lua` declares **`lua_revision = 350453`**. The two are equal.
- **Three separate player-facing gates read that number, and all three pass
  only because the comparison is strict:**
  - `ModDef:IsObsolete()` = `self.lua_revision < ModMinLuaRevision`
    (`Mod.lua:915`) → `350453 < 350453` is **false** ⇒ not obsolete.
  - `ModsUIIsModCompatible(mod)` = `version >= ModMinLuaRevision and version
    <= LuaRevision` (`CommonLua/UI/ModManager.lua:230-234`) ⇒ **compatible**,
    so the Paradox Mods install flow does NOT raise its "The mod <name> is not
    compatible with the current game version… install it anyway?" question
    (`:430-440`).
  - `SavegameMetadata.lua:99` marks a mod obsolete in a save on the same
    `< ModMinLuaRevision` test ⇒ **not** marked.
- ⛔ **This is one integer of margin, not a settled property.** A future patch
  that raises `ModMinLuaRevision` above 350453 flips the browser warning, the
  obsolete flag and the savegame mark simultaneously — for a pack whose Lua
  may still be perfectly functional. **Re-read this const on every game
  update** and record the reading.
- ⚠️ The value is only changeable by the route `editor/version rail (agent/prompts/perma/RELEASE.md § Release rails)` forbids to agents:
  `Mod.lua:979` stamps `self.lua_revision = ModRequiredLuaRevision` on a Mod
  Editor save, which is also the save that bumps `version`. So an agent can
  neither fix nor break this field — it moves only in an owner's sitting.
- See `EF-075` (what the update did to the source base), `EF-076` (the target
  sweep) and `reports/GAME_1_1_0_IMPACT.md` §1d.
