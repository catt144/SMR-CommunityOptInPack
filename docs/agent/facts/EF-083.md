- ⭐ **ROVER-ONLY, READ FROM BOTH TREES** (2026-09-09, link 04b's session, after
  the owner's question). 1.1.0 `LandscapeConstructionSiteBase.lua:40-42`:
  `function LandscapeConstructionSiteBase:ShouldAddRequestToCommandCenter() return
  false -- RCTerraformer only can landscaping, no drones`. The method does not
  exist on 1.0.7 (`:40-46` there is `GetMaxDrones`). `GetUIWarning` (`:157-161`)
  returns the `NoRCDozer` status (`Building.lua:2854`, "No RC Dozer assigned to
  this Landscaping project") unless `IsServicedByRCDozer()` (`:142-152`: any
  `auto_rovers`, or an `RCTerraformer` whose `construction_work` is the site) or
  the `LandscapingNanites` tech. The placement controller adds
  `ConstructionStatus.LandscapeNoDozer` when the colony has no dozer and no Nanites
  (`LandscapeConstructionController.lua:318-321`). `grep -rln "RCDozer\|NoRCDozer"`
  over the archived 1.0.7 `Lua/` returns nothing; over 1.1.0 it returns four files.
  ⇒ [[F115]]'s "whether the dozer rule is NEW is unverifiable" is now VERIFIED: new.
- ⭐ **RESEARCH-GATED.** 1.1.0 `Data/Tech.lua:4895-4933`, tech `TerraformingRover`
  ("Dozer Rover", group `Land`, requires ExplorerAI / TransportOptimization /
  LandOnMars / ExtractorAmplification): `Effect_UnlockResupplyItem RCTerraformer`
  PLUS `Effect_TechUnlockBuilding` for `LandscapeTerrace`, `LandscapeRamp`,
  `LandscapeClearWasteRock`, `LandscapeTextureSandRed`, `…SandDark`, `…SandChaos`,
  `…RockDarkChaos`, `…Mountains`; its description now reads "Unlocks landscaping
  projects and allows the RC Dozer…". 1.0.7 `Data/TechPreset.lua:4453-4465`: the
  same tech (group `Terraforming`) carried ONLY the rover resupply unlock, and no
  1.0.7 tech references any `Landscape*` template except the four lakes. Lakes:
  `LakeCrafting` on both branches (1.1.0 `Tech.lua:10126-10140`, group
  `Terraforming_2`; 1.0.7 `TechPreset.lua:4587-4604`).
- ⭐ **THE BYPASS.** `LandscapingNanites` (a hidden breakthrough, `LockState =
  "hidden"`, `Unknown = true`) carries `Effect_Code` calling `UnlockBuilding` on the
  same eight templates (`Tech.lua:1231-1242`; dev comment "landscaping no longer
  needs the RC Dozer, so this breakthrough makes the projects buildable on their
  own"). `UnlockBuilding` sets `BuildMenuPrerequisiteOverrides[class] = true`
  (`Lua/Tech.lua:163-165`), which the build menu honours over a tech requirement
  (`Lua/X/BuildMenu.lua:798`, `:1926`).
- ⚠️ **WHAT THIS DOES AND DOES NOT TOUCH IN THE PACK.** Nothing in code:
  `Fix_LandscapeUnitFilter` runs at site PLACEMENT (`ConstructionSite:Initialize` →
  `ScatterUnitsUnderneath`), which cannot happen before the tech; `Fix_LakeEntombment`
  is behind the unchanged lake tech. The RC Dozer is an `RCConstructorBase`
  (`RCTerraformer.lua:3-4`), so vanilla's scatter exemption
  (`ConstructionSite.lua:1917`) covers a dozer on the job as it covers a
  constructor. What it DOES change: any landscaping control on a fresh 1.1.0 colony
  must research Dozer Rover first (checklist row 7), and "drones ignore landscaping"
  is vanilla, not the pack.
