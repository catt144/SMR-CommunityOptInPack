- **SOURCE, the hotkey.** `CommonLua/Classes/XDef/CommonShortcuts.generated.lua:176-187`:
  `local cond = AreCheatsEnabled() or ConsoleEnabled or Libs.DevToolsPublic; if cond then XAction:new({ ActionId = "DE_Console",
  ActionShortcut = "Enter", ActionShortcut2 = "Alt-Shift-C", OnAction = ... ShowConsole(true) ... }) end`.
  The condition gates **creation**; a false condition at build time means no action, so no key press can
  reach `ShowConsole`. `AreCheatsEnabled()` is a live GED-window check (`EF-095`), so closing the Mod
  Manager and rebuilding the UI (map load) removes the hotkey. This is the "console keeps getting locked"
  the owner worked around by forcing the console open before loading.
- **SOURCE, the independent arm.** `ShowConsole(visible)` itself gates on `AreCheatsEnabled() or ConsoleEnabled
  or Platform.asserts` (`CommonLua/UI/Dev/uiConsole.lua:429-432`); `ConsoleEnabled` defaults `false`
  (`:425-427`); `ConsoleSetEnabled(enabled)` sets it AND calls `ShowConsoleLog(enabled)` (`:459-463`).
  `ConsoleEnabled` is absent from `ModEnvBlacklist` (`EF-096`). ⇒ setting `ConsoleEnabled = true` directly
  (not via `ConsoleSetEnabled`) gives the hotkey without the on-screen log.
- **SOURCE, `~` is not the console.** `DE_Menu` (`ActionShortcut = "-~"`, `ActionShortcut2 = "\\"`) toggles the
  User Actions menu and is gated at runtime on `AreCheatsEnabled()` (`CommonShortcuts.generated.lua:199-211`).
  `DeveloperInterface:OnShortcut` also consumes `~` under `AreCheatsEnabled()` (`CommonLua/UI/DeveloperInterface.lua:258-266`).
- **SOURCE + OWNER-CONFIRMED, clear screen.** `DE_ClearScreen` (F9) runs `cls() Msg("ClearScreen")` and is created
  with no condition (`CommonShortcuts.generated.lua:189-197`); `cls()` = `dlgConsoleLog:ClearText()`
  (`CommonLua/UI/Dev/uiConsoleLog.lua:133-137`). The owner pressed F9 on 2026-09-13 and it cleared.
- **SOURCE, the console-line tap.** `AddConsoleLog(text, bNewLine)` fires `Msg("ConsoleLine", text, bNewLine)`
  BEFORE `if dlgConsoleLog then` (`uiConsoleLog.lua:116-127`), so a listener receives every console line whether
  or not the on-screen log exists. ⚠️ Whether the native `ConsolePrint` routes through it is unverified (`EF-096`).
- **SOURCE, the every-load reset.** `ResetGameSession()` (`Lua/init.lua:22-42`): `if not Platform.debug then
  config.BuildingInfopanelCheats = false end`; called from `OpenPreGameMainMenu` (`:1-16`) — every visit to the
  main menu, which is how a save is loaded. This is the "re-activate it every time I load".
- **SOURCE, why mod errors go unseen.** Retail (`not Platform.asserts`) block `Mod.lua:2970-3035`:
  `OnMsg.OnLuaError` calls `ReportModLuaError(mod, err, stack)` only when `err` or `stack` contains the mod's
  `content_path`; `ReportModLuaError` returns early if `ReportedMods[mod.id]` is set and sets it on first
  report — **one popup per mod per session**, then silence. `OnLuaError` itself is hookable (`EF-096`), so a
  tool can count every error.
