- **SOURCE — the documented -1 is for a missing object.** "Returns the index of the first spot from
  the given type for the given or default state of the object (-1 if the object does not exist)"
  (`CommonLua/LuaExportedDocs/Game/GameObject.lua:286-292`). It says nothing about a missing spot
  type. `HasSpot(state, typeID)` returns a bool (`:343-348`).
- **SOURCE — shipped callers guard first.** `if self:HasSpot("Top") then ... GetSpotBeginIndex("Top")`
  (`Lua/Buildings/Building.lua:1844-1845`, `Lua/Buildings/StorageDepot.lua:1614-1615`), and the same
  for `"Box1"` (`Lua/Buildings/MultiResourceCubeVisuals.lua:72-73`,
  `Lua/Buildings/ResourceStockpile.lua:276-277`). Presence side: those 4 guards from
  `grep -rn -A2 'if .*:HasSpot("' Lua | grep -B1 GetSpotBeginIndex`. Absence side: 0 hits for
  `GetSpotBeginIndex(...) < 0` or `== -1` / `~= -1` in `Lua/` and `CommonLua/`.
- **OBSERVED — the error.** The Opt-In dev hub's flight counted train doors with
  `while hub:GetSpotBeginIndex("Trackconnector" .. (n + 1)) >= 0 do n = n + 1 end`. On a body with
  six connectors the game raised `HGE::l_GetSpotBeginIndex: Invalid spot` with local
  `state = "Trackconnector7"`, 36 times in log `Mars.exe-20260925-13.34.56` (owner's game,
  2026-09-25, Opt-In `3c47ce2`). Each raise killed the flight's driver thread. The `lupa` smoke
  had passed, because its mock returned -1.
- **HOW TO WRITE.** Ask `HasSpot` (or `CObject.HasSpot` past a class override) before
  `GetSpotBeginIndex`, and count numbered spots by `HasSpot`. Treat a `< 0` test after the call as
  no guard. A mock of `GetSpotBeginIndex` must raise on an unknown name, not return -1.
- **CONTROL.** In game, select any vanilla building and run
  `*r print(pcall(CObject.GetSpotBeginIndex, SelectedObj, "NoSuchSpotName"))`. This fact holds if
  it prints `false` and an "Invalid spot" message, and fails if it prints `true -1`. The
  OBSERVED item is one hub body and one name family; the control makes it general.
