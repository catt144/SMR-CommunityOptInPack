- **SOURCE — the coercion idiom.** Shipped Lua multiplies by `1.0` or adds `0.0` before dividing
  whenever a fraction is wanted: `party_size * 1.0 / remaining_seats` (`Lua/Factions/Factions.lua:180`),
  `value * 1.0 / const.Scale.Stat` (`:510`), `standing * 1.0` (`:396`),
  `fracture.size * 1.0 / guim` (`Lua/Buildings/Dome.lua:1963`), `self.trip_time + 0.0`
  (`Lua/TransportStatistics.lua:56`), `DivAsFloats(self.global_tension or 0, const.Scale.Stat)`
  (`Lua/Factions/Legislature.lua:1344`; also `Lua/XDef/LawEntry.generated.lua:161`). None of this
  would be written if `int / int` already produced a float. Integer results are relied on directly:
  `g_Consts.DroneRechargeTime / 1000` is used as a time (`Lua/Units/Drone.lua:1593`).
- **SOURCE — the helpers are integer functions.** `Min(i1, i2)` "returns the less of the integers",
  `Max(i1, i2)` "the greater from i1 and i2", both `@param int` and `@return int`
  (`CommonLua/LuaExportedDocs/Global/LuaSharedLib.lua:317-333`); `Clamp` returns `int`
  (`LuaExportedDocs/Global/LuaExports.lua:490-496`); `MulDivRound`/`DivRound` are the integer
  rounding divisions (`LuaSharedLib.lua:490-516`); `sqrt`, `sin`, `cos`, `atan` return integers
  "safe to use in synched code, does not use floats" (`:63-133`). Floats exist (`math.type(x) ==
  "float"`, `CommonLua/Core/types.lua:1937`), so this is Lua 5.3 with the division operator
  behaving as integer division for two integer operands, not a float-free engine.
- **OBSERVED — the failure it produces.** Opt-In dev hub build `d77efa4` computed a chord's
  acceleration with `local T = remaining / 1000` (both integers) and passed `math.floor(acc + .5)`
  to `SetAcceleration`; the engine raised `HGE::l_SetAcceleration: Expected integer` on the first
  chord (owner console, 2026-09-23, `*r SpawnHubDrone()`), consistent with `T == 0` and an infinite
  float that `math.floor` cannot make an integer. A `lupa` run of the same Lua passed, because
  standard Lua divides `315 / 1000` to `0.315`.
- **INFERRED — the earlier symptom.** The predecessor build `74b1e4a` sampled its curves with
  `u = Clamp((elapsed - start) / (finish - start), 0, 1)` on integer game times, so `u` could only
  be `0` or `1` in game: the sampler returned span endpoints and the visual stood still, then
  dashed. The owner described that build as "stuttered very bad"; the standard-Lua smoke had
  rendered smooth curves from the same code.
- **HOW TO WRITE.** In mod Lua, coerce before dividing (`a * 1.0 / b`, or a `div(a, b)` helper),
  use `math.min`/`math.max` and a local clamp for float work, and hand the engine integers made by
  `math.tointeger(math.floor(x + .5))` (or `MulDivRound` when the inputs are integers). A mock
  cannot emulate the operator; gate the source instead: refuse a bare `/` outside the helper and
  assert `math.type(v) == "integer"` on every engine argument.
- **CONTROL.** In game: `*r print(7/2, 7*1.0/2, math.type(7/2))` prints `3  3.5  integer` if this
  fact holds and `3.5  3.5  float` if it does not. The OBSERVED item is one console error, not a
  MEASURED division; the operator claim rests on the shipped idiom until that line is run.
