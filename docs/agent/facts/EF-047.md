- **The engine flushes a large log tail only at PROCESS EXIT — a mid-session
  read of the log file is a read of a PARTIAL file** (MEASURED 2026-08-10,
  `corun-batch-2` sitting): the sitting log measured **39,382 bytes when read
  mid-session and 152,783 bytes after the process exited**; the uninstall log
  measured 6,433 mid-session and 6,667 final (that tail was only the exit
  block, but the sitting log's tail was ~113 KB of real content). Per-line
  flush exists (mid-session reads DO see recent `[CB2]` lines), but the lag is
  unbounded in the general case and `FlushLogFile()` was not sufficient to
  close it.

- ⛔ **Consequence: a mid-session read may be quoted for PRESENCE, never for
  ABSENCE.** The measured cost: the sitting ran a console instrument
  (`PEFFECT`), checked the log, saw nothing, and recorded "produced zero
  output — not even its unconditional first line" plus a candidate cause
  ("`ModLog` unreachable from the console sandbox"). The final log contains
  all five `PEFFECT` lines (`cb2sitting…log:379-383`, `[mod]`-prefixed, so
  `ModLog` IS reachable) — the output existed; the mid-session check could
  not see it. Both recorded claims were corrected by the terminal audit.

- ⚠️ Scope: every mid-session log read this project took before 2026-08-10 was
  of a partial file. Absence-of-line verdicts in those reads are only safe
  where the final archived log was re-checked — which the per-leg audits do.

- ⚠️ **A second, independent cause of a partial read: `FlushLogFile()` itself
  lags console output by ~5-10 seconds** (owner, 2026-08-02, "noticed in many
  sessions"). A flush issued immediately after a console command can land
  BEFORE that command's output reaches the file, so the log shows the command
  and not its result. When asking for a console reading, tell the owner to
  wait ~10 seconds before flushing; if a reading appears to be missing from a
  flushed log, suspect this lag before suspecting the command failed. This
  cause is distinct from the exit-only-flush measurement above — the tail can
  be short because the process has not exited, or because the flush was
  issued too early after the command that produced it.
