- **WHERE MOMENTS LIVE.** `GetEntityAnimMoments(entity, anim, type)` resolves
  `GetAnimEntity(entity, anim)` (engine) and returns
  `Presets.AnimMetadata[anim_entity][anim].Moments`, filtered by `Type`, else an
  empty table (`AnimMoment.lua:5-16`). Every `CObject` moment method goes through
  it. `ReloadAnimData` (`:367-381`) also pushes the presets to the engine, but the
  Lua lookup does not need that: a preset created by `PlaceObj('AnimMetadata', …)`
  registers itself (`Preset:__fromluacode` → `Register`, `CommonLua/Preset.lua:562-581`,
  `:667-676`) and is visible at once. Moments may be plain `{Type =, Time =}`
  tables — the lookup reads only those two fields.
- **ONLY 5 GROUPS SHIP PRESETS** (1.1.0; 4 in 1.0.7): `AdvancedStirlingGenerator`,
  `BakeryHands` (DLC `norman`), `CaveIn_Buildings`, `CaveIn_UndergroundDome`,
  `CaveIn_UndergroundMicroDome`. Any other entity reports 0 moments of every type,
  whatever its animation looks like. A `.hgacl`/`entities.dat` scan finds no `Hit`
  strings because moments are not stored there on this engine.
- **THE INDEX TRAP.** `obj:GetAnim(1)` returns a NUMBER (MEASURED `anim 20 number`
  on the Rare Metals hammer, log `Mars.exe-20260910-11.47.24-6a91a190.log:255`).
  The lookup indexes `preset_group[anim]`, so a number hits the group's ARRAY
  part and returns nil. Correct callers convert: `GetChannelData`
  (`AnimMoment.lua:107`), `GetAllAnimMoments` (`Building.lua:3347`). Broken
  callers: `BaseBuilding:TrackMultipleHitMoments` (`:1045-1046`), `Metatron.lua:52-57`.
- **PROOF, attended 2026-09-10:** a preset for the hammer + a class-level numeric→name
  conversion made the game's own tracker play the authored strike FX, heard in sync.
- ⚖️ Measured: the hammer's index, the count 0 with a preset present, the live fix.
  NOT measured: `GetAnimEntity` for other entities (it can map one entity's
  animation to another's name — resolve it before keying a preset).
