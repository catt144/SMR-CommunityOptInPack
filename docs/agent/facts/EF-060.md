- **The seam, proven live.** `TaskRequestHub:FindTask(agent, flags)` wraps
  `Request_FindTask_C` over the hub's `priority_queue` / `supply_queues` /
  `demand_queues` and returns `(request, pair_request, resource, amount,
  priority)` (`_TaskRequest.lua:71-83`). The `c48-pairing` leg (2026-08-16,
  `archive/c48pair2_*`) carried 25,184 calls and 985 supply+demand pairings
  through a log wrapper there with zero wrapper errors and zero `[LUA
  ERROR]` — the seam tolerates instrumentation at full colony load.
- ⭐ **The class-constrained re-query.** `FindSupplyRequest(agent, resource,
  amount, min_priority, ignore_flags, required_flags, exclude_building,
  measure_from, max_dist)` and the demand twin (`:54-69`) hand both flag
  filters to the C finders — so policy code never re-implements matching: ask
  for "a supply carrying `rfStorageDepot`" (depot-only feeding) or "a demand
  carrying it" (bank loose pickups to storage) and the engine's own distance,
  reachability, restrictor-table and claim arithmetic produce the candidate.
  Substitute it into FindTask's return; fall back to the original pairing
  when the re-query resolves nothing (never starve a consumer for a policy).
- **Queue anatomy for scans** (read live in the same leg): per hub,
  `supply_queues[priority][resource]` / `demand_queues[...]` are plain Lua
  arrays of request userdata, priority −1..`MaxBuildingPriority`; vegetation
  seed offers sit at p1 (their class declares `priority = 1`), depot supplies
  mostly at p0 with player-prioritized depots at p2/p3.
