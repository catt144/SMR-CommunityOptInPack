- ⭐ **`TaskRequestHub:FindTask` HANDS C NINE VALUES AND READS NOTHING ELSE OF
  `self` BUT THE LAP FIELDS; `Request_FindTask` IS A REACHABLE GLOBAL.**
  (Source-read 2026-09-01, spot-checked twice — `BANDS_CLEAN_REVERT` and its
  review.) `Lua/_TaskRequest.lua:71` is `local Request_FindTask_C =
  Request_FindTask` — a file-local ALIAS of a global a mod can call directly;
  `:72-83` passes exactly `self.priority_queue, self.supply_queues,
  self.demand_queues, self.under_construction, self.restrictor_tables,
  ResourceUnits, agent and agent.unreachable_buildings, flags, agent`, and the
  only other `self` reads in the body are `lap_start`/`lap_time` bookkeeping
  (`:77-81`). `self` itself is never handed to C. ⇒ a **stand-in "hub"** for a
  direct call is a plain table with the five queue-ish fields plus the two lap
  fields — the basis of the view-tier designs (opt-in
  `reports/DRONE_BANDS_CLEAN_REVERT_20260901.md` §4.2 V; whether C honours a
  mod-built table set is still E-4(iii), do not assume it).
- ⭐ **THE PERSIST WALK NEVER DESCENDS INTO CLASS TABLES, `_G`, OR A MOD ENV.**
  (Source-read 2026-09-01.) All three are PERMANENTS — substituted by label,
  not walked: `_G` at `persist.lua:61`/`:104`, `g_Classes` and every class
  table by name at `:157-165`, each loaded mod's env as `"Mod/<id>"`
  (`Mod.lua:1642-1644`). ⇒ a table that is reachable ONLY as an upvalue of a
  function stored in a class table (e.g. a wrapper's transient caches) has no
  route into a save. ⚠️ The guard is the word ONLY: the same table reaches the
  save the moment a persisted thread frame, a game object field, or a
  `GameVar` also references it (`EF-022`, `EF-023`) — and a FUNCTION stored on
  an INSTANCE is serialised by value precisely because permanence stops at the
  class-table boundary (`EF-069`).
