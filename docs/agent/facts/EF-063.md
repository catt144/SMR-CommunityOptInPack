- ⭐ **Where the translations actually are.** The retail install carries
  **nine** language packs — `A:\SteamLibrary\steamapps\common\Project Spark\Local\`
  holds `Brazilian`, `English`, `French`, `German`, `Polish`, `Russian`,
  `Schinese`, `Spanish`, `Turkish` `.fpk` (plus `Voices\English.fpk`). Each is an
  FLPK container holding exactly one file: `CurrentLanguage/Game.csv`.
  `IsLocalizationLanguageAvailable(language)` resolves to
  `"Local/" .. language .. ".fpk"` in a non-developer build and
  `OptionsData.Options.Language` is built only from the packs that exist
  (`CommonLua/Core/localization.lua:1209-1227`). ⇒ **the language menu is a
  directory listing**, and every one of those nine is a real player route.
- ⭐ **Reading one costs 30 seconds, with our own tool.**
  `python -c "import sys; sys.path.insert(0,'tools'); import flpk_extract;
  flpk_extract.extract(r'<game>\Local\German.fpk', r'<out>')"` → one
  `CurrentLanguage/Game.csv`, 43,110 rows, columns
  `ID,Text,Translation,Old Text,Old Translation,Status,…,Location,Context,…`.
  The `Location` column names the source file and line the record was extracted
  from, which is how you tell an orphaned record from a live one.
- ⛔ **`ModTools\Game.csv` is NOT that file.** It is the English export
  (28,321 rows, `ID,Text,Translation,VoiceActor,Context`, Translation column
  empty or echoing the English). It is a modding reference, not the table the
  game loads. Useful as a first pass — an id absent there is absent from the
  packs too — but a presence check there proves nothing about a given language.
- ⭐⭐ **The rule.** `T(id, text)` renders `TranslationTable[id]` when the id is
  enrolled and falls through to the embedded literal when it is not
  (`EF-039`, whose live control was discharged 2026-08-02:
  `type(T(8821,"ZZZ"))` → `userdata`, log `Mars.exe-20260802-20.28.19`).
  ⇒ **enrolment is the whole question**, and it is checkable rather than
  arguable.
- ⚠️ **An XDef-generated id can be missing from the packs, and its own siblings
  prove it is not systemic.** Worked example (`C51`): the Universal Rocket's
  *Back to Earth* button uses `885571832096` / `807999655245`
  (`Lua/XDef/customUniversalRocket.generated.lua:23-24`), **neither in the
  German pack** — while the other **7 of 7** ids in that same generated file are
  enrolled, one carrying the literal location `…customUniversalRocket.generated.lua(00015)`.
  So "XDef ids just aren't translated" is false; run the sibling control before
  concluding either way.
- ⭐ **Both directions matter, and they point opposite ways.**
  * **Pointing a UI at an ENROLLED id is loss-free in retail** — the id already
    carries every language, so the fix adds no English anywhere (`C51`).
  * **Replacing an enrolled id's text with a new literal regresses eight
    languages** — the new id is in no pack, so it renders English for everyone
    who is not playing in English (`C50`). `EF-039` route 3,
    `shipped_T .. Untranslated("…")`, appends without loss; route 4,
    `ModItemLocTable`, is the only way to supply new translated text and it
    overrides the SHARED table for vanilla and every other mod.
- ⚖️ **What is measured and what is not.** The pack inventory, the extraction,
  the row counts and every id lookup quoted above were performed on this rig
  2026-08-16 and are MEASURED. That a non-English player *sees* the fallback
  English on screen is SOURCE-plus-inference: no leg has switched the game's
  language and looked. Do not upgrade the wording without that screenshot.
