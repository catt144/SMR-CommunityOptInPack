### The 142 `MapData/` entries above are per-map data, and they are readable too (2026-09-12)

- ⭐ **Per-map data is NOT in `ModTools/Src`** — `Data/MapData/__load.lua` there
  is a stub. Each `Packs/Maps/<map>.fpk` (the same 142 this entry already
  counted as `Data.fpk`'s asset-only `MapData/` share) holds a compiled
  `mapdata.lua` (`\x1bLuaS` bytecode, ~1.3 KB, zstd-wrapped). `flpk_extract.py`'s
  `parse_table` plus its zstd loop pulls every one out in seconds; a
  printable-string dump of the decoded chunk gives every string constant. A
  compiled chunk stores only NON-default properties, so a key's presence
  (`IsRandomMap`, `map_location_exclude`, a `GameStates` list) means it was
  explicitly set — check the default in `CommonLua/Classes/MapData.lua` /
  `Lua/ClassDefs/ClassDef-Default.generated.lua` before reading absence as
  "off". Booleans themselves are not decoded by a plain string dump.
- ⭐ **Why it mattered.** REACHABILITY_AUDIT (07-30), BLIND_AUDIT and a Codex
  sweep (09-12) all left `F31`'s reachability open on "binary mapdata not
  greppable". One string dump settled it — `UndergroundAnomalies` appears only
  on the 16 underground blanks, `BuriedWonder` lists on no map — and turned a
  KEEP into a RETIRE. "Not in Src" is not "not readable", and a search of the
  packed bytes is no sample until they are decoded.
- ⚠️ A pack's `mapdata.lua` carries the date of the patch it was built for —
  Mar-21 surface blanks vs Sep-08 underground blanks measured on 1.1.0 — so a
  file dated before the current patch is the previous version's map data, the
  only 1.0.7 map data still on disk.
