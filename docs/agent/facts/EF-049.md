- **`Savegame.ListForTag("savegame")` is NOT a stable save-liveness witness.**
  On 2026-08-04 (`unattended-1` cycle 0) it returned a table whose count moved
  **57 → 58** across an in-run save — the witness that PROVED the SAVE
  primitive. On 2026-08-10 (`corun-batch-2` sitting) it returned a
  **non-table on all five saves** (`TRY Savegame.ListForTag … ok=true
  result=-1`, the instrument's non-table encoding; `-1 -> -1` on every
  before/after pair), on the **same build** (retail 1.0.7.396349), while all
  five saves demonstrably landed. Cause unknown; state-dependence is the open
  hypothesis, and nothing here establishes it.

- ⛔ **Consequence: the SAVE primitive's liveness witness is the file system,
  not the API.** The witness that actually carried 2026-08-10: `SaveGame`'s
  own `err=false`, the file's on-disk size/mtime read agent-side, and a
  successful `LoadGame` of the file. A brief that gates a leg on `ListForTag`
  movement will void the leg on a day the call returns non-table.

- ⚠️ This is also the "per-chain facts never live in per-process flags" rule's
  sibling: a PROVEN primitive's witness is re-proven per sitting, not
  inherited — the proof was real, and it still stopped replicating six days
  later.
