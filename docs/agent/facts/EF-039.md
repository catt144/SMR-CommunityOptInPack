- **RE-USING A SHIPPED TRANSLATION ID TO CHANGE TEXT IS A NO-OP IN RETAIL — the
  engine discards the replacement literal at `T()` construction** (source-read
  2026-08-02, chain prompt 9; **live control queued, see the caveat**). This is
  the fact that makes `Fix_TechDescriptionBuilding` a shipped no-op (**BUGS F98**)
  and it binds every player-visible string this pack ever writes.
  * **The mechanism.** `T(id, text)` ends with
    `if not dev and not Platform.ged and TranslationTable[id] then return
    LocIdToLightUserdata(id) end` (`CommonLua\Core\localization.lua:250-252`, and
    the sibling branch `:270-272`). `dev` is `Platform.debug or
    Platform.developer` (`:3`) — **false in retail**. So the call returns a light
    userdata carrying only the id and **your string never leaves the call**.
    Rendering then reads `TranslationTable[id]` (`:662`) and prints the shipped
    text.
  * **English is not the exception.** It is a loaded translation table like any
    other — the install ships `Local\English.fpk` beside nine more, and
    `LoadTranslationTables` (`:970-985`) hard-asserts if the folder is missing in
    a non-developer build. There is no retail configuration that reaches the
    embedded literal by this route.
  * **⭐ The three routes that DO put text on screen, exhaustively:**
    1. ~~re-use a shipped id~~ — dead, per above;
    2. **`Untranslated("…")`** — `T{str, untranslated = true}` carries no id, so
       the table lookup misses and `TDevModeGetEnglishText` returns the literal
       (`:75-92`). Works in retail; the string is whatever language you wrote;
    3. **`shipped_T .. Untranslated("…")`** to **append** to existing localized
       text with **zero loss in any language**. `TMeta.__concat` (`:373-412`)
       works on the stripped light-userdata form because
       `LightUserDataSetMetatable(TMeta)` (`:359`) installs TMeta as the shared
       light-userdata metatable; `IsTCompatible` is `return_true` in retail
       (`:23`); `_InternalTranslate` handles the resulting `TConcatMeta` (`:756`).
       **Shipped precedent: `sign..Untranslated(amount)`,
       `Lua\Buildings\Workplace.lua:293, :299`.** Concat can only ADD — it cannot
       delete a wrong sentence out of a shipped string.
    4. *(and a fourth that is not a code route)* **`ModItemLocTable`** — mods
       genuinely can ship per-language CSVs, merged into the shared
       `TranslationTable` when `loctable.language == GetLanguage()`
       (`Mod.lua:2277-2307`, `ModItem.lua:1069-1093`). ⚠️ It merges into the
       **shared** table, so an id written there is overridden for vanilla and
       every other mod too. **This is the route the owner chose 2026-08-02**, and
       it is post-release work.
  * ⚖️ **WHAT IS MEASURED AND WHAT IS NOT** (own-medicine,
    `recorded-facts-are-claims`): **all of the above is SOURCE-READ, none of it
    is observed.** The corroborating circumstantial evidence is strong —
    `TMeta.__newindex` asserts *"in Gold Master they could be a userdata instead
    of a table"* (`:441`), which is the engine saying the same thing — but no leg
    has watched it. ⛔ **A 30-second live control is queued for the next attended
    sitting and settles it either way:** `ModLog(type(T(8821, "ZZZ")))` —
    **`userdata`** means the literal was discarded and this entry is right,
    **`table`** means it survived and this entry (and F98) is wrong. **Do not
    build a text fix on this reading before that runs.**
