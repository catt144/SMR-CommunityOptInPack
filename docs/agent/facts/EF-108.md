- **The charge, and the only one.** The sanity reason `"cold wave"` renders as *"It's too cold"*
  (`Lua/Interests.lua:152`) and has exactly one writer: `Colonist:HourlyUpdate`
  (`Lua/Units/Colonist.lua:4533-4556`), once per in-game hour:
  `if HasColdWave(self:GetMap()) then local dome = self.dome; if not dome or GetHeatAt(dome) < dome.freeze_heat then`
  → `self:ChangeSanity(-damage, ... "cold wave")` at `:4555`. The dev comment on that `if` names what it
  models: *"this effect is the fear from the cold outside"*. It fires only while a Cold Wave disaster
  is active; living in a dome is not an exemption.
- **What the dome's heat reading actually is.** `GetHeatAt(obj)` (`Lua/Heat.lua:160-164`) samples the
  map's `heat_grid` at the object's position, or returns `const.MaxHeat` out of bounds. For a dome that
  is the outside grid at its **centre point** — the dome writes nothing to that grid. Its threshold is
  the `ColdSensitive` default `const.DefaultFreezeHeat` (`Lua/Buildings/ColdSensitive.lua:9`); no dome
  template overrides it (`grep -ln "Dome" Lua/BuildingTemplate/*.generated.lua | xargs grep freeze_heat`
  returns nothing, while the same grep over all templates finds `freeze_heat = 91` on `SmartHome` and
  others, so the search works). ⇒ A large dome is all-or-nothing on heater coverage, decided by whether
  its centre is in range.
- **Who is spared, and how much the rest take.** Exempt: Martianborn colonists once
  `g_MartianbornStrength` is set by the tech, and any colonist on an `expedition_rocket`. `Coward`
  doubles it. `dome:GetDamageDecrease()` (a Security Station) cuts it by a percentage, and the reason
  then reads `"cold wave with securitystation"`. The remainder is scaled by
  `60 + BraidRandom(self.handle + 7403, 100)` percent — a FIXED personal multiplier of 60–159% per
  colonist, seeded from the handle, so two colonists in one dome take different amounts every hour.
- **What ends it.** Temperature's `ColdWaveStop` threshold is 50% with hysteresis 2
  (`Data/TerraformingParam.lua:149`). `OnMsg.TerraformThresholdPassed` sets `ColdWavesDisabled`,
  calls `StopColdWave()` and removes the disaster notifications (`Lua/TerraformingDisasters.lua:5-13`).
  Independently, any Temperature change applies ambient temperature to the heat grid
  (`OnMsg.TerraformParamChanged`, `Lua/Terraforming.lua:296-300`), which lifts `GetHeatAt` at every dome.
- ⛔ **NOT TRACED: when the threshold message fires.** `SetTerraformParam` emits `TerraformParamChanged`
  but not `TerraformThresholdPassed`; that comes from `UpdateTerraformingThresholds` (`Terraforming.lua:168`),
  and no caller was found for it with a `UpdateTerraformingThresholds()` grep. So whether setting
  Temperature to 100% (the SMRTK `open_domes` leaf, TestKit `82d4577`) stops a running cold wave at once
  or on a later tick is unmeasured. The heat-grid route above acts on the change itself.
- **Control — what would falsify this.** During an active cold wave, a colonist whose dome's centre sits
  inside a working heater's radius should log no *"It's too cold"* line for that hour, and the same dome
  with the heater switched off should. A colonist in that dome still charged while covered refutes the
  single-point reading. ⚠️ Not run.
- **Observed, uncontrolled (owner screenshot, 2026-09-17, 1.1.0.403908).** `Colonist(2000000690)`, a
  dome resident, logged *"It's too cold"* −1, −10 and −7 on Sols 16, 17 and 18, with the cold wave's frost
  visible on the terrain. Consistent with the above. ⚠️ INFERRED, not traced: the sanity log appears to
  total the hourly charges per sol, which would make −1 a wave that began late on Sol 16.
- **Not a defect.** The code does what its own comment says, so there is no self-contradiction to file.
  The single-point sample is a design simplification. Use this fact to answer a field report asking why
  colonists complain of the cold inside a dome; no entry is filed.
