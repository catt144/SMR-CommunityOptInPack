- **SOURCE — the buffer and its size.** Saving and loading "work from/to a preallocated memory
  buffer … can be reallocated by changing config.MemorySavegameSize" (`CommonLua/Savegame.lua:20-23`);
  the game sets `config.MemorySavegameSize = 96*1024*1024` (`Lua/Config/config.lua:56`). Loads use
  the same buffer, so a save larger than the cap cannot be opened on a stock game either.
- **SOURCE — where the message comes from.** "Block Error" appears nowhere in the Lua tree; it is an
  engine string in `Mars.exe` (one occurrence), stored beside `Memory block is not sizable`,
  `block size is exceeded` and `trying to change size of static memory block`. The autosave failure
  handler passes the engine's error string straight into the dialog
  (`CommonLua/Savegame.lua:1459-1461`), which falls to the generic "Unidentified error while saving
  <savename>! Error code: <error_code>" (`CommonLua/Core/error.lua:76`, `:100-109`).
- **SOURCE — a player cannot change it without a mod.** The console opens only with cheats or
  `ConsoleEnabled` (`CommonLua/UI/Dev/uiConsole.lua:429-430`), and cheats are dev builds or active
  modding tools (`CommonLua/gamelib.lua:1014-1016`, `CommonLua/Modding/Mod.lua:146-148`).
  `AppData/LocalStorage.lua` runs in a data-only `LuaValueEnv` (`CommonLua/Core/GlobalStorageTables.lua:294-295`),
  so a `config` line there does nothing. `AreModdingToolsActive()` is also true while the Mod Manager
  is open; whether that opens the console mid-game is untested.
- **OBSERVED — owner-attended, this rig, 2026-09-27.** Log `Mars.exe-20260927-14.44.01-6aad2d75.log`
  (copy in `local/save-buffer-fix/logs/`): L268 `MSS before 100663296`; L270 set to 1 MB, then a
  manual save gives L272 `[Persist Error] Save game failed (Terrain), error is Block Error, stream
  size is 4194304` and the same dialog (L274-278); L280 set to 256 MB, then the save is written
  (`Europe Sol 280 (2).savegame.sav`, 31.6 MB, 14:45:08) with no error. ⇒ the value is read at save
  time; no restart is needed.
- **OBSERVED — the mod route, same day.** Log `Mars.exe-20260927-14.52.18-6aad2d75.log`: L71 loads
  `SMR_SaveBufferFix` unpacked from AppData (no portal upload); L292
  `[SaveBufferFix] MemorySavegameSize 100663296 -> 268435456` before mod items finish (L302) and
  before any save loads; L374 console read `268435456`; manual save written 14:53:22.
- **THE FIX, kept locally, not in the pack.** `local/save-buffer-fix/` holds the tested mod (two
  files: `metadata.lua` and `Code/SaveBufferFix.lua`, which raises the value to 256 MB and never
  lowers a larger one), `SaveBufferFix.zip` (hash-identical to the tested copy) and both logs. It must
  stay enabled: the value is config, not saved. Progress since the last good save is lost unless the
  game is still open and a console mod is running.
- **OWNER RULING, 2026-09-28: the player copy stays NOT optional.** In the owner's words: *"For
  others her its probably good to be marked not optional. If she accidentally ticks it off and plays
  for 3 or 4 hours without noticing and she never got the warning she wouldn't be able to save."*
  The missing-mod warning is the player's only signal that the fix is off. ⛔ Do not add
  `optional_mod` to `local/save-buffer-fix/` or the zip. The owner's own installed copy
  (`%APPDATA%\Surviving Mars Relaunched\Mods\SaveBufferFix`) carries `'optional_mod', true,` and is
  kept disabled there, only to silence the warning on the owner's saves; it differs from the
  reference copy on purpose.
- **SOURCE — why a removed mod keeps warning, and what silences it.** A save's `active_mods` list
  only grows: `GetLoadedModsSavegameData` starts from the loaded save's own list and adds the running
  mods (`CommonLua/SavegameMetadata.lua:11-31`), so re-saving without a mod keeps its entry. The
  warning (`:344-350`) skips a mod when `mod_def.optional_mod` or the saved entry's `optional` is
  true (`:94-104`); `mod_def` is read from `Mods`, which holds every installed definition, enabled
  or not (`CommonLua/Modding/Mod.lua:1766-1795`). ⇒ an installed, disabled, optional copy silences
  the warning on every save without re-saving. Source only; not yet observed in game.
- **FIELD REPORT — the reach.** Rohoma (Discord, 2026-09-27): a Sol 1,588 colony, autosave and manual
  save both fail with Block Error. This rig's Sol 280 colony saves at 31.6 MB. The same player
  reports 10 sols per 2 real hours, 12 min per sol: effective 1×, where the retail ceiling of 5×
  (EF-038) gives 24 min. The sim is throughput-bound on that colony; the cause is unmeasured.
- **NOT ESTABLISHED.** Loading a save above 96 MB with the mod (no such save exists here); any engine
  limit above 256 MB; whether other mods also set the value. Not filed as a pack
  defect, and no owner ruling on shipping it in the pack.
- **CONTROL.** In a loaded colony, set `config.MemorySavegameSize = 1*1024*1024` and save: the fact
  holds if the save fails with `Block Error`, and fails if it saves. Then set `256*1024*1024` and save
  again: it holds if the save is written. A future build that sizes the buffer dynamically makes the
  first step save, and this fact moves.
