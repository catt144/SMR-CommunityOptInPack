- **Why it was an open question.** Every prior walk this project has driven named a
  *placed* class. `DroneControl` is a mix-in parent only — it appears in the
  `__parents` of `DroneHub`, `RocketBase` and `RCRover` (Src-verified 2026-08-12)
  and is never instantiated directly. `corun-pt60`'s prep listed it as a stop
  condition ("whether `AllMapsForEach` accepts the mix-in class `DroneControl` —
  never driven") and `STATE.md` carried it as unresolved, so the P9 leg was built
  with its own enumeration witness rather than trusting a zero.

- **MEASURED 2026-08-12**, `corun-pt60` attended sitting, log
  `docs/archive/cp60sitting_Mars.exe-20260812-13.38.15.log:1003-1016`, on the
  owner's Sol-302 campaign save:

  ```
  COUNT DroneControl :: n=19 | walk ok=true
  COUNT DroneHub     :: n=11 | walk ok=true
  COUNT RocketBase   :: n=0  | walk ok=true
  COUNT RCRover      :: n=2  | walk ok=true
  P9 enumeration witness :: base-class DroneControl walk saw 19 (ok=true) |
      concrete DroneHub+RocketBase+RCRover walks saw 13
  ```

- ⇒ **`AllMapsForEach(true, "<mix-in class>", fn)` works, `pcall`-clean, and returns
  MORE than the enumerated concrete descendants** (19 vs 13). The gap is real
  descendants the three-class list does not name, so a leg that walks concrete
  classes "to be safe" can UNDER-count. Prefer the base class and cross-check.

- ⛔ **The false-clean shape this witness exists to catch did NOT occur**, and the
  test is worth reusing: a base walk of **0** beside concrete walks finding objects
  means the enumeration failed, and a zero from a failed walk is indistinguishable
  from a true absence unless both are printed. Any absence claim over a class walk
  should carry a second, independent walk.

- ⚠️ **SEPARATE FINDING, reported not tidied away: `RocketBase` walked 0 while the
  same colony's `UIColony.labels.AllRockets` held 6 rockets** (read minutes earlier
  by `CP60.Fixture`). So `RocketBase` is not the placed class for that colony's
  rockets — the concrete class is elsewhere in the rocket hierarchy (`ClassicRockets`
  / `UniversalRocketBase` family). ⛔ **Do not build a rocket leg on the name
  `RocketBase` without a population read first**; the walk succeeds (`ok=true`) and
  returns nothing, which is the quietest possible failure.

- Related: EF-047 (absence only from archived logs), EF-048 (truthiness/type, never
  `== true`) — this read printed raw counts and the `ok=` flag for both walks.
