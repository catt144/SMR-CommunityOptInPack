- **`GameRandom:Random` — BOTH FORMS MEASURED 2026-08-02 (PT-61 phase 4.0b), on
  `SessionRandom` in a live retail colony, 2000 draws each.** The two arities do
  NOT use the same bound convention, and the difference is load-bearing for any
  fix that draws a count.
  * **`Random(max)` → `[0, max - 1]`.** Measured `min 0, max 99` over 2000 calls
    to `Random(100)`, and `under 50` came up **1005 of 2000** — a fair coin. This
    corroborates the derivation from the class's own `TableRand`
    (`Lua\GameRandom.lua:14-19`), which does `local idx = 1 + self:Random(count)`
    and then indexes a `count`-element table — only sound if the one-arg form
    stops at `count - 1`. **So `SessionRandom:Random(100) < N` is exactly an
    N% gate**, which is what the shipped disaster code assumes
    (`DustDevils.lua:169`, `Meteors.lua:284-290`).
  * **`Random(min, max)` → `[min, max]`, INCLUSIVE.** Measured `min 6, max 8`
    over 2000 calls to `Random(6, 8)`, with the top value appearing **652 of
    2000** (32.6% against a uniform 33.3%). ⭐ **This had only ever been
    INFERRED** — from the property help text (*"Lo Range / Hi Range"*,
    `DustDevils.lua:9-10`) and from the sibling `AsyncRand`/`BraidRandom` doc
    comment (`CommonLua\LuaExportedDocs\Global\LuaSharedLib.lua:22`, *"random in
    the interval [min, max]"*). `GameRandom:Random` delegates to the **native**
    `RandState:Get` (`GameRandom.lua:10-12`), so no Lua source states its
    contract and the inference could not be checked by reading.
  * ⚠️ **Why it was worth 4000 draws to settle:** F97's headline claim is that a
    preset's `count_max` becomes *reachable*. If the two-arg form had been
    half-open, `Random(6, 8)` could never return 8, and the claim would have been
    false for a reason in the engine rather than in the fix — with the leg
    happily measuring the wrong thing. **A native function's bounds are a claim
    until something observes them.**
  * ⚠️ **Sampling note, recorded because the wrong lesson is easy to take here:**
    two earlier small samples of the same gate read low (15/40, then 179/400,
    about −2.5σ pooled) and prompted this measurement. The 2000-draw run came
    back at 978 (−1.0σ) and tracked the raw roll's 1005 within noise, so the
    early readings were variance. **The pooled figure across all three (1172 of
    2440, ≈ −1.9σ) is not evidence of anything** — it was computed only *because*
    an early sample looked odd, and it pools windows of very different size. Take
    the largest single sample; do not pool after the fact to rescue a suspicion.
