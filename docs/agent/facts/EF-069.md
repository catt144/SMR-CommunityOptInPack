- ⛔ **A CLASS-LEVEL `GetPriorityForRequest` OVERRIDE ENTERS SAVES BY VALUE —
  `RequiresMaintenance.lua:94` writes it per instance.** (Source-read 2026-09-01,
  `BANDS_CLEAN_REVERT`; not yet measured — E-6 in the opt-in mod's
  `reports/DRONE_BANDS_CLEAN_REVERT_20260901.md`.) `RequiresMaintenance:InitMaintenanceRequests`
  (`Lua/RequiresMaintenance.lua:75-97`; called at construction from `Building.lua:329`, on a
  resource change at `:382`, and by the `FixMissingMaintenance` fixup `:571`) takes its `else`
  branch for every building whose `DoesRequireMaintenance()` is false (`:105-107`:
  `maintenance_resource_type == "no_maintenance"`, or destroyed) and executes
  `self.GetPriorityForRequest = g_Classes[self.class].GetPriorityForRequest or
  TaskRequester.GetPriorityForRequest --flatten` (`:94`) — a FUNCTION VALUE written onto a
  persisted instance. `OnMsg.PersistGatherPermanents` registers `g_Classes` and each class
  TABLE by name (`CommonLua/Core/persist.lua:157-165`), never the functions inside them, so the
  walk serialises that value by bytecode + upvalues — the EF-022 route, executed by vanilla on
  its own function today (benign). With a mod's chained wrapper installed on
  `TaskRequester.GetPriorityForRequest` at file scope (flattening copies it into every building
  class, EF-058), `g_Classes[self.class].GetPriorityForRequest` IS the wrapper, and every
  no-maintenance building constructed while the mod is installed carries the mod's closure —
  with its upvalues (`orig`, any file-local helper, and the mod env as `_ENV`) — in the save.
  After uninstall the fallback env resolves vanilla globals only (EF-023): a body that touches
  `SMROptInPack.*` throws on the next `AddBuilding`/`_InternalAddRequest`
  (`DroneControl.lua:693`, `CommonLua/TaskRequest.lua:312`); a body that opens with a nil-global
  orphan gate runs its by-value copy of vanilla's function forever, inert. Either way it is a
  mod closure on a game object that the mod cannot remove. ⭐ The devs met the same trap: the
  2018 public drop's `maintenance_request_is_highest_prio` urgency (Spirit
  `Lua/RequiresMaintenance.lua:45, :81-87, :382-388`; removed 2018-05) needed a
  `SavegameFixups` pass that `rawset` the method back onto every `RequiresMaintenance` object
  (public `Lua/SavegameTempCompatibilityFixes.lua:595-601`, HaemimontGames/SurvivingMars — not
  in the Relaunched tree); the field survives in our Src as `RequiresMaintenance.lua:53`
  "save compat with rev 225026 saves". ⇒ Rule: never change urgency by overriding
  `GetPriorityForRequest` on a class any no-maintenance building inherits; re-file requests by
  table surgery on the hub's own queue tables, or substitute at `TaskRequestHub:FindTask`
  (EF-060). Falsifier (E-6): a no-maintenance building built under such a wrapper, saved,
  loaded WITHOUT the mod → `rawget(bld, "GetPriorityForRequest")` returns a function, and a
  `ReconnectTaskRequesters()` on its hub either throws naming the mod or runs the orphan.
