- **SOURCE, game 1.1.0.403908: `ChooseResidence` never tests `destroyed`, and does not need to —
  the test is INHERITED one level down.** `GetResidenceComfort`
  (`Lua/Buildings/Residence.lua:416-434`) opens with `if not ValidateBuilding(residence) then
  return end`, and `ValidateBuilding` (`Lua/Buildings/Workplace.lua:1316-1327`) rejects
  `destroyed`, `demolishing`, `refab_work_request` and `exceptional_circumstances`. So comfort is
  **nil** for a destroyed residence, `ChooseResidence` maps nil to `min_int` (`:454-455`), and the
  only tie-break that could still select such a candidate (`:459`) requires
  `best_home ~= current_home` — FALSE for a homeless colonist, since both are `false`.
  ⇒ **a destroyed residence can never win selection.**
- **The other two routes agree, by different means** (both sides counted, so this is not a
  one-sided read): `MicroGHabitatBase:ChooseResidence` (`Lua/Buildings/MicroGHabitat.lua:162-171`)
  is a SEPARATE selector that never calls comfort and tests `self.destroyed` directly at `:164`;
  `Dome:GetLivingSpace` (`Lua/Buildings/Dome.lua:2554-2562`) writes `not obj.destroyed and
  obj.ui_working` out longhand over the same `labels.Residence`. Three routes, no gap — and the
  apparent asymmetry (the selector leaning on the comfort gate) is cosmetic, not a defect.
- ⇒ it is IRRELEVANT that `Building:Destroy` removes the building from no label and leaves
  `ui_working` true (`:1570` clears `working`, not `ui_working`). Those facts are true and lead
  nowhere; a lead framed on them is closable at source.
- ⛔ **THE DESK-HARNESS CONSEQUENCE, and it cost a false finding that passed a full audit** (F59
  "A3", filed and retracted the same day, 2026-09-11). Stubbing `GetResidenceComfort` to a constant
  — `function() return 50,0 end`, which looks inert because comfort SCORES are not what such a test
  measures — DELETES the validity guard above. A leg then shows a colonist assigned into a
  residence being destroyed, repeatably, in a fixture that could not have produced the right answer.
  **A stub for a body that can REFUSE (return nil, validate, reject) is a behaviour change, not a
  tolerance:** shim what the shipped code needs to RUN, never what it uses to DECIDE.
  Tell: a claim turning on an object's unusual STATE (destroyed / demolishing / dying / disabled) is
  exactly what validity helpers test. Both halves are pinned as legs in
  `tools/desk_f59_interact.py` (`real_comfort=True` loads the shipped bodies) so the artefact cannot
  be re-derived. Full record: `agent/bugs/F59.md`'s retraction section.
