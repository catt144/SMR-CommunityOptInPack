- **GAME-TIME THREADS PERSIST BY DEFAULT — real-time threads do not** (popup
  audit 2026-07-30; the F83 investigation briefly assumed the opposite and
  retracted a fix recommendation on it). `MakeThreadPersistable`
  (cthreads.lua:224-230) exists to CLEAR the flag on GT threads
  (`XWindow.lua:1578` clears it on a maybe-GT thread) and to SET it on RT
  threads (`_fixup.lua:36`, `Notifications.lua:215` — their GT twins go bare);
  `OnMsg.PersistPostLoad` (`_fixup.lua:50-66`) expects global GT threads to
  arrive through the save. Persist serializes blocked STACKS —
  `PersistGatherPermanents` (cthreads.lua:451-464) registers `Sleep`/`WaitMsg`/
  `WaitWakeup`/`CObject.PlayState` as "sleeping function[s] found in the thread
  stack" — and preserves shared-reference identity across one save's graph.
  Corroborated in play constantly: unit command threads are bare
  `CreateGameTimeThread` (CommandObject.lua:100) and resume mid-command after
  every load. Consequences: a consequence computed after a wait is safe in a GT
  thread and LOST in an RT thread (the F83 family); "no MakeThreadPersistable"
  on a GT thread is the SAFE default, not a missing call.
- ⭐ **EXTENDED 2026-09-11 — what happens when the thread's OWN BODY cannot be
  persisted, which decides whether deferral is safe for a MOD.** Persist does not
  fail the save: it substitutes `__unpersisted_function__` (`CommonLua/Core/persist.lua:52-54`),
  whose whole body is `assert(false, "Unpersisted function!")` — and by `EF-008` an
  assert does not unwind, so on load that thread simply **ends**. ⇒ a mod's deferred
  work is either restored intact (if its closure serialises) or **silently dropped,
  degrading to vanilla behaviour** — the correct failure direction, and neither
  outcome corrupts the save. ⚠️ Which branch a given closure takes is UNMEASURED;
  it does not need to be, because both are safe. ⛔ Do not lean on this in place of
  an orphan gate: a restored thread runs with the mod ABSENT, which is what
  `if not SMRFixPack then return end` as the first statement after the only yield is
  for (`Fix_FreedHousingNotice`, `Fix_ExtenderFlapChurn:97`; rule in `FIX_POLICY` §4).
  Found while auditing F59's deferral repair — ⚠️ and found the long way: that
  section of `bugs/F59.md` re-derives the persistence half of THIS fact from source
  without having read it first. Check this index before deriving an engine claim.
