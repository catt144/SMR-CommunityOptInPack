- ⭐⭐ **A BUILT CLASS'S `Init` IS NEVER THE FUNCTION ANYONE ASSIGNED — `Init` and
  `Done` are COMBINED methods, composed per class at build time** (source-read +
  measured 2026-08-20, close-out links 4-5). `DefineCombinedMethod("Init",
  "procall", "InitDone")` (`CommonLua\PropertyObject.lua:1663-1664`);
  `OnMsg.ClassesPreprocess` (`CommonLua\Core\classes.lua:1602-1676`) walks each
  hierarchy, collects every classdef's own `Init` into a method list
  (`:1643-1646`), generates one NEW closure per distinct list (`:1647`) and
  writes it back into the classdef (`:1672-1674`) before classes are built.
  * ⭐ **This works FOR a classdef-time wrapper.** A wrap installed on a parent's
    classdef before build is CAPTURED into every descendant's composed `Init` —
    including descendants absent from `_G` at install time. Measured at the link
    4 sitting: `C51` wrapped ONLY `customUniversalRocket` (`link4de_*`: "wrapped
    on 1 rocket class(es)") and the Zeus rocket's panel patched anyway, German
    rollover on screen. The five-subclass install loop kept in
    `Fix_LocalizedUIText.lua` repaired nothing; this mechanism is why.
  * ⛔ **It blinds wrapper-identity probes.** After build, `<class>.Init` equals
    NEITHER the installed wrapper NOR the captured original — deterministically,
    every boot, zero other mods. The wave-12 TestKit probe's clause 1 therefore
    prints *"a later mod has chained on top of ours on TerraformingOverall,
    customUniversalRocket — legitimate"* on every run (`link4de_*:468`); the
    cause it names cannot be the cause (link 4 flagged the wording, link 5
    re-derived the mechanism at Src). ⚠️ Worse than a wording flaw: a wrapper
    genuinely LOST before `ClassesPreprocess` would produce the SAME "neither"
    reading and the same reassuring PASS — clause 1 cannot detect install loss
    on a combined method. The probe's real coverage is its stats counters
    (clause 6) and a screen. ⇒ TestKit maintenance item (separate repo, NOT in
    the 82-file pack); fix the taxonomy there before trusting clause 1 again.
  * ✅ **Identity checks stay VALID on plain methods and globals.** The class
    builder copies plain members by REFERENCE and nothing recomposes `_G`
    functions, so wave-13's comparisons on `GetSponsorSummary`,
    `GetSponsorDescr` and `LandingSiteObject.GetMissionSponsorEffect` all read
    equal-to-ours in the same sitting (`link4de_*:473`, no chained-over clause).
  * ⚠️ **THE UNSWEPT QUESTION THIS SURFACED (link 5's C5, 2026-08-20).** The
    pack wraps ~60 (class, method) targets (`{ class = …, method = … }` Require
    entries across `Code/`), and no audit has ever enumerated, per target, the
    shipped SUBCLASSES that OVERRIDE the wrapped method — an overriding subclass
    keeps its own function and the parent wrap never runs there. `C51`'s rocket
    half is the only place the question has ever surfaced. Failure mode is
    UNDER-COVERAGE — the unreached subclass keeps vanilla behaviour, defect
    included, and every wrapper declines to vanilla by design — never new harm,
    which is why link 5 did not block 1.0.0 on it. A systematic sweep is
    post-release / opt-in-era maintenance work, not a launch item.
  * ⛔ **THE 2026-08-24 "SHARPENING" WAS WRONG AND IS WITHDRAWN — REFUTED BY
    MEASUREMENT THE SAME DAY** (`F106`, closed; log
    `archive/f106_Mars.exe-20260824-02.32.27.log`). It claimed that the class
    builder's copy branch (`ResolveValues`, `classes.lua:700-709`) made a wrap on
    an un-`__hierarchy_cache` declaring class miss **all** subclass instances,
    overriding or not, and named `Fix_SmallLandscapeSites` (F33) a suspect
    no-op. **The premise "post-ClassesBuilt" is false.** `SMRFixPack.Register`
    applies **inline at file-load time** (`Code/00_Core.lua:452`; mod files load
    at `ModsLoadCode()`, `autorun.lua:423`, which precedes the `Msg("Autorun")`
    raise at `lib.lua:371` — `autorun.lua:556-557` is the handler, not the
    raise — where `classes.lua:980` builds the classes). So plain-method wraps
    patch **classdefs** and the builder copies OUR function into every
    descendant. ⇒ **the same capture this fact already records for combined
    `Init`/`Done` holds for PLAIN METHODS too**, by a different mechanism (the
    builder's member copy, not `ClassesPreprocess`'s composition). F33 measured
    clean on all three leaf classes. ⚠️ Two citation corrections to carry
    forward: `classes.lua:986-988` states the flatten/chain split **INVERTED**
    against the code and must not be used as corroboration; and only
    `SMRFixPack.DataPatch` waits for `ClassesBuilt` (`00_Core.lua:334`).
  * ✅ **THIS WATCH'S ORIGINAL QUESTION IS NOW ENUMERATED — MEASURED 2026-08-24**,
    same log, probe `DispatchReach` (`TestKit/Code/64_Probes_Wave14.lua`), over
    every `{class, method}` target the pack declares:
    `targets=105 clean=97 with-unreached=8 missing=0 | descendants=13127
    reach=1981 UNREACHED=66 | MULTI-PARENT=11080 (of which unreached=1328)`.
    ⚠️ **The pack declares 105 such targets (100 distinct pairs, 46 classes) —
    this fact's standing "~60" was an estimate and is LOW**; the count is
    generated by `tools/harvest_wrap_targets.py`, never hand-typed. The 66 + 1,328
    unreached are exactly what this watch asked about: shipped subclasses that
    RE-DECLARE the wrapped method. Two spot-checks at Src — `RCConstructorBase`
    declares both interaction methods `Fix_RocketInteractGuard` wraps on
    `RCTransport` (`RCConstructorBase.lua:341`/`:356`); `Building` re-declares
    both `GetWorkNot*Reason` that `Fix_ShuttleHubOffAvailable` wraps on
    `BaseBuilding` (`Building.lua:591`/`:598` vs `BaseBuilding.lua:326`/`:355`),
    which is the 578-of-627 reading on that target. Failure mode is unchanged:
    UNDER-COVERAGE, never new harm. ⛔ **The sweep does NOT measure which of those
    classes are ever INSTANTIATED**, so the hit count is a reach gap and never a
    broken-fix count; that half of checklist 74 stays unmeasured.
  * ⚠️ **THE REAL DEFECT THE SWEEP FOUND IS THE MIRROR IMAGE — `F107`.** Because
    the pack wraps classdefs, a module that captures `local prev = C.Method` on a
    class which does not itself DECLARE `Method` captures **nil** (a classdef
    holds only its own members and has no metatable). `Fix_LandscapeCostRefresh`
    does exactly that on all three landscape leaf classes; MEASURED, filed as
    `F107`. Static audit: the pack's only instance. ⇒ **the authoring rule this
    fact now carries: wrap the class that DECLARES the method, or capture the
    original from the declaring class — and self-check the pair you install on,
    not merely a pair on the same class.**
