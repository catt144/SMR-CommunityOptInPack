- **The engine imposes no Lua-side clamp on the requested factor.**
  `Colony:SetGameSpeed(factor)` (`Lua\Colony.lua:564-592`) passes straight to
  `SetTimeFactor(const.DefaultTimeFactor * factor, true)`. `const.ultraGameSpeed
  = 20` (`Lua\_GameConst.lua:28`) is a **UI convention**, not a limit — the HUD's
  top button, nothing more.

- **⭐⭐ BUT THE EFFECTIVE RATE IS THROUGHPUT-BOUND, AND IT IS NOT MONOTONIC IN
  THE REQUESTED FACTOR.** MEASURED 2026-08-11 (`corun-pt15` attended sitting,
  log `docs/archive/cp15sitting_Mars.exe-20260811-15.09.30.log`, L833-L853), five
  20-real-second probes, effective rate computed as game-ms advanced ÷ real-ms
  elapsed:

  | requested | applied (read back) | **effective, MEASURED** | hour transitions | skipped hours |
  |---|---|---|---|---|
  | 20× | 20× | **20.00×** | 14 | 0 |
  | 50× | 50× | **50.00×** ⭐ | 34 | 0 |
  | 100× | 100× | **21.22×** | 15 | 0 |
  | 200× | 200× | **32.55×** | 22 | 0 |
  | 400× | 400× | **20.72×** | 15 | 0 |

  ⇒ **50× is the highest factor that actually delivers what it asks for.**
  Above it the sim cannot sustain the step and the delivered rate collapses to
  roughly ultra or below — asking for 400× runs the game **2.4× slower** than
  asking for 50×.

- **⚠️ CONDITIONS, because this is a measurement and not a property of the game.**
  One machine (i7-14700K / RTX 4080), one save (`CP15STAGE`, a ~48 MB colony at
  ~25 sols, 1 dome, ~24 colonists, **1 sinkhole** — audit correction 2026-08-11:
  the log reads `sinkholes=1` minutes before the probes; 6 was the day-70
  count), one moment. ⚠️ The agent was
  reading the log file off disk during the probes, so the >50× figures carry
  unquantified I/O contention; the **dip-then-recovery (21× → 33× → 21×) looks
  like noise rather than a clean ceiling** and those three numbers should be read
  as "collapsed and unstable", not as precise rates. The 50.00× result is exact
  (1,000,000 game-ms over 20,000 real-ms) and is the one to rely on.

- **⭐ THE HOUR-SKIP HAZARD WAS NOT REACHABLE.** The predicted failure mode —
  a frame advancing more than the 5,000 game-ms `SinkholeBase` polls at, so an
  `hour == 22` equality is never observed and wisps silently never spawn — did
  **not** occur at any rung. The probe reproduced that exact poll (a game-time
  thread sleeping 5,000 ms) and saw **zero skipped hours even at 400×**, because
  the effective rate never climbed high enough to skip one. ⇒ on this machine the
  sim's own throughput ceiling protects the equality checks. ⛔ Do NOT generalise
  this to a faster machine: the arithmetic predicting a boundary near ~300×
  stands, it simply is not reachable here.

- **⚠️⚠️ A CONSOLE-SET SPEED DOES NOT SURVIVE THE UI, AND THE FAILURE IS SILENT.**
  Everything the HUD does routes through `SetGameSpeedState` (`Lua\X\HUD.lua:
  527-545`), whose whole vocabulary is `pause` / `play` / `medium` / `fast` /
  `ultra` — and **`"play"` is hardcoded to `UIColony:SetGameSpeed(1)`**.
  Dismissing a popup takes that path. MEASURED in the same sitting: a march set
  to 50× was found running at **1×** after one notification was answered, and the
  only reason it was caught is that every `CP15` leg prints `speed=Nx` in its
  `CLOCK` line. ⇒ **re-assert the factor after every popup**, and never trust a
  console-set speed across a UI interaction.
  * Pausing is safe for the setting: `last_speed` is only recorded when the
    factor is above zero (`if factor > 0 then last_speed = factor end`,
    `Colony.lua:586`), and `SetGameSpeed()` with **no argument** restores it.

- **⛔ HARNESS LESSON — "highest safe rung" is the WRONG selector, and the
  sitting's own instrument got it wrong.** `CP15.SpeedRamp` picked `best` as the
  highest rung reporting SAFE and recommended **400×**, then *set the game to
  it* (`SPEEDRAMP restored speed: SetGameSpeed(400)`). Safety and throughput
  diverge precisely because a rung can be "safe" **by being slow**. Any future
  ramp must rank by *measured effective rate among safe rungs*, not by safety
  alone. The recommendation was overridden by hand in the sitting.
