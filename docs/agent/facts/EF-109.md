- **What the table is.** `SetupBuildingTemplateTables` (`Lua/Buildings/Building.lua:2674-2684`) rebuilds
  `BuildingTemplates` as `setmetatable({ template_name = id }, g_Classes[id])` per preset (`:2680`,
  commented `-- !!! temp onlys`). A value has `template_name`, not `id`; `.id` falls through to the
  class and reads nil. `BuildingTemplatesPresets[id]` holds the real preset.
- **When it is filled.** Only on `OnMsg.ClassesBuilt` (`:2686`) and on `DataChanged` with no class list
  or with `BuildingTemplate` in it (`:2688-2692`). On a cold boot ClassesBuilt fires before presets
  load, so at `DataLoaded` the table holds no DLC template; it fills on the `DataChanged(false)` that
  `CommonLua/Dlc.lua` posts from a thread after DataLoaded (`:715-717` -> `:686-690` -> `:683`).
- **Use instead.** Presence: `BuildingTemplates_Raw[id]`, which `Preset:Register` fills as each preset
  file loads (`CommonLua/Preset.lua:573-580`; the GlobalMap is declared at `Building.lua:2556`), so it
  is complete at DataLoaded. Labels and class fields: `g_Classes[id]`, the class a placed building is.
- **Measured.** C107's first build read `BuildingTemplates` in a DataPatch pass and went `error` on the
  owner's first boot (log `Mars.exe-20260918-17.51.56-6a91a190.log`): the DataLoaded pass logged "none
  of the four Feeding the Future plant farms is loaded", then each DataChanged pass threw "table index
  is nil" on `labels[template.id]`. The Opt-In Pack's MultipleSuns logs the same timing two lines
  earlier ("BuildingTemplates.ArtificialSun not found", found at the next pass). The corrected build
  (`e8608f9`) booted clean. `tools/desk_c107_dry_farming.py` reproduces both lines in cold-boot order.
