- **SOURCE, the flag.** `GameVar("CheatsUsed", false)` and `LogCheatUsed(method, obj)` append
  `{ GameTime(), method, obj.class, obj.handle }` (`CommonLua/Libs/Network/Network.lua:241-245`).
  A GameVar persists with the savegame, so one call taints that colony for its whole life.
  `AreCheatsUsed()` = `CheatsUsed and #CheatsUsed > 0` (`:247-249`).
- **SOURCE, the consequence.** `OnMsg.UnableToUnlockAchievementReasons` adds `reasons["cheats used"]`
  when `not Platform.asserts and AreCheatsUsed()` (`Network.lua:251-255`). `CanUnlockAchievement`
  (`CommonLua/Classes/Achievement.lua:16-21`) collects reasons via that message; the full set of
  handlers is four: cheats used (above), `AreModdingToolsActive()` (`CommonLua/Classes/GedModEditor.lua:23-27`),
  a game rule with `DisableAchievements` (`Lua/GameRules.lua:154-160`), and `g_Tutorial` (`Lua/init.lua:44-48`).
  ⭐ **Mods being loaded is not a reason** — nothing in `CommonLua/Modding/Mod.lua` adds one.
- **SOURCE, the only three writers** (`grep -rn LogCheatUsed ModTools/Src` → 4 hits: the definition + 3 callers):
  `NetSyncEvents.ObjCheat` → `InvokeObjCheat` logs per object (`Network.lua:208-216`);
  `NetSyncEvents.Cheat` logs then calls `_G[method](...)` (`:230-239`);
  `NetSyncEvents.CheatDef` logs then `def:run(...)` (`CommonLua/Classes/ClassDefs/ClassDef-PresetDefs.generated.lua:943-949`).
  ⇒ The bodies those wrappers call contain no logging. `Building:CheatCleanAndFix` is
  `self:Repair(); self.accumulated_maintenance_points = 0` (`Lua/Buildings/Building.lua:1944-1947`);
  `CObject:CheatDelete` is `DoneObject(self)` (`CommonLua/Classes/_cobject.lua:1591-1593`);
  `Building:CheatDestroy` clears `indestructible` then `DestroyBuildingImmediate(self, {reason = "cheat"})` (`Building.lua:1923-1930`).
- **SOURCE, the split inside the preset menu.** `CheatDef:Exec()`: `if self.sync then NetSyncEvent("CheatDef", ...) else self:run(...) end`
  (`ClassDef-PresetDefs.generated.lua:907-913`); `sync` defaults to `true` (`:853-854`).
  **MEASURED** on `Data/CheatDef.lua`: 105 presets, 22 carry `sync = false` (`grep -c "sync = false"`), so
  83 taint through the wrapper and 22 run bare. ⚠️ 13 of the bare ones re-enter `NetSyncEvent("Cheat", ...)`
  inside their own `run` and taint anyway — the list is in `EF-098`.
- **SOURCE, the per-object panel.** The infopanel "Cheats" section is `Data/XDef/sectionCheats.lua`
  (`__condition config.BuildingInfopanelCheats and context:CreateCheatActions(parent)`, `:11`); its
  buttons dispatch through `NetSyncEvents.ObjCheat`, so **every button there taints** (Fill, Empty,
  Delete, Destroy, CleanAndFix, Malfunction, AddPrefab, Spawn*, Upgrade1-6 …).
- **SOURCE, enabling is not tainting.** `config.BuildingInfopanelCheats` occurs six times in the tree
  (`Data/CheatDef.lua:413`, `Data/XDef/sectionCheats.lua:11`, `Lua/Cheats.lua:210`, `Lua/init.lua:37`,
  `Lua/UI/InGameInterface.lua:905`, `Lua/XDef/sectionCheats.generated.lua:16`) and none is an
  achievement-reason handler. The `ToggleInfopanelCheats` preset that flips it is `sync = false`
  (`CheatDef.lua:410-421`), so even flipping it from the cheat menu writes nothing.
- **SOURCE, the transient block.** `AreCheatsEnabled()` = `Platform.cheats or AreModdingToolsActive()`
  (`CommonLua/gamelib.lua:1014-1016`); `AreModdingToolsActive()` = `IsModEditorOpened() or IsModManagerOpened()
  or IsModEditorMap() or Game.testModGame` (`Mod.lua:146-148`), and the first two are `FindGedApp(...)` —
  a **live** window. Close it and the reason is gone; nothing is stored.
