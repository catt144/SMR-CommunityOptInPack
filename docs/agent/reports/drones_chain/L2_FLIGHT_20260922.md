## Implemented surface

SOURCE (this implementation): a vanilla `FlyingDrone` is created with `init_with_command=false`
and the hub as `command_center`. It has no custom command and never enters drone pathfinding.
The prototype stays outside the hub's dispatch list, sets its battery to its configured maximum
on every sample, and is deleted if commanded, reassigned, destroyed or its hub disappears.
Ordinary Wasps are untouched. L4 must add its scoped control wrapper and fleet integration.

The route walks physical station connectors and existing track endpoint owners, with visited
stations and tracks, retaining broken originals and excluding unfinished new track. It sorts
a copy of each track's elements by `node_idx`; no vanilla list is mutated. Reciprocal tunnel
links add a timed hidden segment. BFS chooses the first reachable route, not a shortest-distance
route. Return reverses its route; an early recall retraces the flown prefix. A recall already
on the normal inbound leg preserves its deadline.

Each segment duration is distance / speed rounded to game milliseconds. Pit launch and landing
each have their own total duration. Work uses `constructStart`, `constructIdle`, `constructEnd`
and `Construct` FX directly; start/end use the Wasp's animation durations, and no request is
created or fulfilled. Console status exposes absolute `arrival`, `work_done` and `removed`
deadlines. `work_done` includes the end animation, which L4 must distinguish from economic
completion. No large-network responsiveness claim is made from the small mock fixture.

GUESS defaults for L3: `HoverHeight=300` engine units above each rail element's visual origin,
`Speed=6000` units/game second, `LaunchTime=3000`, `LandingTime=3000`, `WorkTime=5000` game ms.
The pit constants implement the ruling, not a guessed centre launch. `BatteryMax=800000`;
`Palette=false` until a visual verdict. The real-time driver samples game time every
`SampleTime=20` real ms, so pausing does not advance the trip. This is direct position sampling,
not native flight physics, banking or smooth pathfinding.

## Console use for L3

All lines below are **[NEVER RUN in game]**. Select the built hub first, then select the desired
track element or broken element's construction site after launching. The console calls do not
yield and need no game-time wrapper.

```lua
SpawnHubDrone()
SendHubDroneTo(SelectedObj)
SMROptInHubFlight.Status()
ReturnHubDrone()
SetHubDroneTune("HoverHeight", 300)
```

`SpawnHubDrone` and repeated sends to the same target are idempotent. A send to a different
target while busy refuses with a reason. `ReturnHubDrone` is idempotent and lands/removes the
visual. A tuner call refuses while the console drone exists; call it after landing.
Other tuner names are `Speed`, `LaunchTime`, `LandingTime`, `WorkTime`; use positive integers.
Errors return `nil, reason` (tuner: `false, reason`), so inspect both results on refusal.

## Reusable API for L4

The `SMROptInHubFlight` table exports:

- `PitPoints(hub)` and `Route(hub, target)` return world points / route or `nil, reason`.
- `Create(hub, started)` returns an **ephemeral** flight record containing its vanilla drone.
  `started` defaults to `GameTime()` and can be an earlier absolute time.
- `Send(record, target, keep_start)` constructs the full round trip. Pass `true` for
  `keep_start` when reconstructing: no hover wait is inserted and the start is not reset.
- `Update(record, now)` samples any record; returns false and removes the visual on completion
  or invalidation. It does not perform economic work. L4 can drive multiple records separately.
- `Remove(record)` and `ClearAll()` remove visuals with FX cleanup. `Status()` describes only
  the console flight, not L4's fleet.

Do not persist these records: plans hold transient object references. L4 owns the persisted
pending record, authoritative deadline, scheduling, economic completion and rearm. Derive the
visual's absolute start from the authoritative deadline and the plan's offsets, not from the
load time. Current tunables affect newly built plans; preserve deadline authority if values
changed since dispatch. Samples after a deadline advance to the appropriate segment or remove
the expired visual rather than restarting it.

The driver is a real-time thread and calls a synchronous sampler; it places no blocking mod
game-time frame in a save. Its lookup/gate is the dev mod's own `SMROptInHubFlight`, because this
dev mod also works without the shipping `SMROptInPack` framework. Layers 3/2 cannot express the
full ride solely through vanilla inputs/tail calls. Layer 1 removes **all registered visuals**
at `SaveGameStart`, blocks every spawner through `SaveGameDone`, and cancels the console flight.
Load and game end clear the registry. L4 must recreate its jobs from persisted deadlines after
the gate clears; this file intentionally cannot resume a console job after save. Native manual
save/autosave/failure/load and long-deadline checks remain owed, including EF-070's save race.
