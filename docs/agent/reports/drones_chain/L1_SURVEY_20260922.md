## Answers carried to the build

### Work kinds

**SOURCE:** broken and new track use construction requests. The work resource is `construct`;
the group owns materials and work, and the concrete completion dispatch is
`ConstructionGroupLeader:Complete()` to each `TrackConstructionSite:Complete()`. The generic
`ConstructionSite:Complete` citation in `DESIGN.md` is imprecise; calling the live group
leader's method is the normal dynamic route (`EF-112`).

**SOURCE:** station upkeep is two jobs: material demand, which a station can self-fill from its
own stock, then a `repair` work request that still needs a worker. Maintenance completion also
clears dust. The decoded 1.1.0.403908 tree has no separate clean-work producer: the four positive
`CleanNeeded`/`DroneCleanAmount` lines exist, but none creates a `clean` request. Ordinary intact
track and ordinary track tunnels expose no recurring maintenance job (`EF-113`).

**SOURCE/INFERRED:** work radius controls automatic request discovery, not a universal physical
ban inside `Drone:Work`. Track connectivity grants no drone-task coverage. Manual assignment can
bypass `FindTask`, but still uses real request assignment, approach and fulfilment; exact
arbitrary-distance landing/pathfinding remains a game concern. Do not widen track work to upgrades,
refabrication, destructive clearing or unrelated disabled drones without an owner ruling.

### Work presentation

**SOURCE:** the broken-track site's native sequence is `constructStart` → `constructIdle` →
`constructEnd`, with FX action `Construct` (`EF-112`). `repairBuildingStart` / `repairBuildingIdle`
/ `repairBuildingEnd`, action `Repair`, is building maintenance/clear work. `Drone:Work` itself has
no fixed visual; it mutates a real request, approaches and calls the target. Link 2 should play the
construction visual directly with cleanup, never fake a request for presentation.

### Battery, palette and control

**SOURCE/MEASURED arithmetic:** default `battery_max` is 80,000 stored units. Idle seeks charge at
`<= 12,000` (15% of the default) and a consuming command interrupts at `<= 6,000` (7.5%); both are
absolute thresholds. Holding a repair Wasp at its raised maximum clears both (`EF-115`).

**SOURCE:** the vanilla palette surface is
`Building.SetPalette(object, cm1, cm2, cm3, cm4)`; the recharge precedent applies it to the
platform. It structurally accepts a valid colorizable Wasp, but which `DroneJapanFlying` materials
respond is a visual-prototype question. `Drone:CanBeControlled()` gates both reassign buttons;
link 4's chained wrapper returns false only for a Wasp whose live controller is the train hub and
passes the original result through for every other drone.

### Network reachability

**SOURCE:** `ForEachConnectedTrack` is one-hop, has no visited set and calls `GetDestStation`.
`GetDestStation` returns false while any element is under construction; the construction site made
by a track break enters that array. The helper can therefore hide the broken edge and the component
beyond it. Nil/zero callbacks cannot distinguish genuine isolation from a broken first edge
(`EF-114`).

**INFERRED implementation:** build a hub-rooted physical graph with explicit visited-node and
visited-track sets. Enumerate connector tracks, cross an existing broken track by its still-live
`GetStartStation`/`GetEndStation` owners, and add reciprocal tunnel-mouth `linked_obj` edges. Do not
use cached train routes, `CanTrainsRun` or helper emptiness as reachability authority. The runtime
smoke must cover a break before/after traversal, a remote isolated component, a tunnel and a cycle.

### Pit

**MEASURED:** imported `Pitfloor` and `Pitrim` are entity-local
`(-999.999634,-577.349792,-2000)` and the same XY at z `30.000002`; the floor-to-rim rise is 20.30 m.
The 11.50 m mouth is substantially roofed, but a clear static Wasp column exists by offsetting both
spots by entity-local `point(-310,180,0)` at native scale. That is a 3.584690 m floor offset. Against
a conservative 1.752370 m yaw-independent Wasp radius, measured minimum margins are 0.355809 m to
overhead geometry and 0.400629 m to the shaft. A 13,248-ray swept-box sample found 0 blocked rays.

**INFERRED recommendation:** spawn/return at the offset `Pitfloor`, script a level lift/descent
through the matching offset `Pitrim`, and hand off above the deck at local z +10 m. This requires no
geometry change. Banking, cargo, simultaneous drones, moving trains and live attachments remain
prototype/smoke concerns. The exact ruling is OI-25; link 2 remains held for it.

### Save boundary

**MEASURED/SOURCE, existing facts:** a blocked game-time command persists its function, locals and
upvalues by value (`EF-023`/`EF-027`). Mods receive `SaveGameStart`/`SaveGameDone`, including the
autosave path (`EF-024`/`EF-030`), but game time can run between the start message and the persist
walk (`EF-070`).

**INFERRED layer-1 shape:** persist only the pending record and absolute deadline. At
`SaveGameStart`, raise a save gate and remove track-mode visuals/commands. Every spawner must honor
the gate until `SaveGameDone`; then rebuild from `Max(0, deadline - GameTime())`, including the
failed-save path. Load performs the same validation/re-arm and never restarts a full trip. Test a
manual save, autosave, reload, failure recovery and long deadline. The two internal save paths that
skip both messages remain a stated limit.
