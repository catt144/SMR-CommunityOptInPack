### D15 — Service interest tags (design, display only)  `[built — Code/Opt_ServiceInterestTags.lua, desk-verified 2026-09-28; not yet seen in game]`

⚖️ **Owner ruling, 2026-09-28** (verbatim, relayed by the fix-pack seat's brief
`SERVICE_INTEREST_TAGS_BUILD_high.md`, consumed by this entry's commit):
*"can you actually author a brief in the opt in mod, to create a new interest tags opt in. That
would add this info in the construction panel when you hover of the building and add a ui panel
that has a interest / tags section for the build UI when its already out?"*

It asks for two surfaces: the build-menu hover of a service building, and an interests section on
a placed building's infopanel. Off by default, one Mod Options toggle (`ServiceInterestTags`),
vanilla UI with it off.

**Classification (FIX_POLICY §4).** A behaviour choice, display only: no rule about how colonists
choose or use services changes. Off is byte-vanilla behaviour. Not a donor-declined repair:
1.1.0 removed the display along with its strings, and nothing marks that as unintended.

**Why a player needs it — SOURCE, 1.1.1.405907.** Interests still drive play. `Service:SetCustomLabels`
files a building under one label per interest (`Buildings/Service.lua:170-230`), which
`Dome:GetService` (`Buildings/Dome.lua:3622`) searches for a colonist's daily interest. The Gamer
and Extrovert traits pay Sanity on entering a working building whose interests include Gaming or
Social (`Units/Colonist.lua:2671-2678`). The UI shows the category ("Stores") and never the
interests, so a player cannot see that an Electronics Store counts for Gamers.
**Prior art — SOURCE, 1.0.7.396349:** `Service:GetIPDescription` appended
`T{376972917568, "Services: <em><list></em>"}` (`Buildings/Service.lua:58-62`, again `:190-194`),
and `sectionVisitors` ended with `"Needs serviced: <ServiceList>"` (`XDef/sectionVisitors.generated.lua:44`).
Neither id is in the 1.1.1 `Lua` or `Data` trees (grep, 2026-09-28).

**Reachability — R1 live.** Hovering any service building in the build menu reaches
`X/BuildMenu.lua:832`; selecting a placed one builds `ipBuilding`, which creates `sectionVisitors`
(`XDef/ipBuilding.generated.lua:72`) and `sectionFoodService` (`:75`). No console step is involved.

## Control — what the in-game look must show

With the toggle ON: hovering an Electronics Store shows `Interests  Gaming, Shopping` under
`Service  Stores`; a placed Casino Complex's Visitors section ends with
`Interests  Social, Gaming, Luxury / Gambling`; a placed Diner's food block shows
`Interests  Social, Dining, Food`. Any of those missing, a second Interests row, or a changed
vanilla line FAILS it. With the toggle OFF, the same three views must be vanilla. A log line
`ServiceInterestTags: inactive (… not found …)` means a self-check fired. Routed to the fix
pack's checklist (both mods loaded in one game, owner 2026-09-18) with the steps in its
`docs/agent/reports/OPTIN_SERVICE_INTEREST_TAGS_20260928.md`.
